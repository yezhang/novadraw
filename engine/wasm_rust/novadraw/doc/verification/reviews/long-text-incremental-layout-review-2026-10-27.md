## 右侧拼接边界的证明

**LTI-R01，P1。** 方案要求检查新旧两侧拼接证据，但尚未写出右边界证据如何取得。
HarfRust 0.3.2 的 `unsafe_to_concat` 说明明确区分 cluster 起点和片段末端：
没有直接对应 end-of-text 的位置，需要 shaping 比复用片段更多的文本，
在内部 cluster 边界取得证据。最后一个 glyph 的标志不能直接证明片段末端安全。
该事实由本机固定版本源码核对。[cite:1](#source-1)

修订应说明候选边界的选择、delta 映射，以及旧侧和新侧在对应拼接位置的检查。
右端额外 shaping 的范围必须纳入实际扫描与输出成本；证据失败时向外扩大，
直到取得证据或回退整段。抵达真实段落末端时，需要明确采用的段落上下文和终止规则，
避免把任意局部片段末端当成真实段落末端。

**复核标准：** 正文或配套伪代码能明确指出每个拼接位置的证据来源；
不以最后一个 glyph、`unsafe_to_break` 或旧侧单独无标志证明安全。
验证计划包含片段右端、真实段落末端、Arabic joining、跨边界连字和连续扩张，
使用同版本完整 shaping 作 oracle。提供不了证据的引擎保留整段路径。

## 检查点恢复与跨版本状态等价

**LTI-R02，P1。** Parley 0.7.0 的 `break_next` 可向前逐行计算，
`revert` 只恢复上一次计算前的状态；其公开接口没有提供跨编辑的检查点导出和导入。
`Layout::break_lines` 创建新的 breaker，不能仅由逐行接口推导出持久检查点恢复能力。
内部状态还包含 run、cluster、候选断点与 emergency boundary 等信息。
这证明当前公开能力的边界，尚不能证明适配或上游扩展不可行。[cite:2](#source-2)

修订应把宽度变化的完整重新换行与编辑后的检查点恢复分开评估。
默认引擎需要明确采用适配器、上游扩展或独立算法中的哪条候选路径，
指出仍需核验的接口和状态；未获证据时保留完整换行，不能将该路径登记为已可交付。
外部引擎通过同一能力合同声明是否支持恢复。

跨版本复用还需区分新快照 revision、整段分析身份和局部资产证书。
编辑通常产生新整段资产，检查点有效性不能只要求整段身份相等，
也不能只因后缀字节相同便忽略新的 bidi、字体及换行状态。
应定义经 delta 映射后可继续复用的局部证书、依赖和状态等价条件，
由新组合快照统一拥有当前来源映射、位置投影和交互 revision。

**复核标准：** 给出检查点生成、失效、映射、恢复和后缀复用的完整过程，
说明状态的所有权、版本兼容性、数值检查及失败回退。
验证计划覆盖断点相同但状态不同、新段落资产引用有效旧后缀、
旧快照留存、inline 反馈和不支持恢复的外部引擎。
不能把一次 `revert` 或重建后从段首扫描称为跨编辑检查点恢复。

## delta 映射与失败归属

**LTI-R03，P2。** 方案已规定多个编辑使用旧版本坐标，但尚未冻结插入边界的映射规则。
检查点、样式端点和来源范围都依赖同一映射；仅规定顺序、重叠和长度仍不足以消除歧义。
既有文字交互合同使用 UTF-8 position 与 upstream/downstream affinity，
delta 的边界偏向需要明确说明与该交互 affinity 的关系。

修订应定义半开区间、合法 UTF-8 边界、长度溢出检查、同位置插入顺序，
以及插入端点和删除范围内位置的映射结果。
还需定义来源身份、版本链连续性、delta 合成规则及 split/merge 后来源映射的归属。
可以选择拒绝某些歧义输入，也可以规定确定顺序，正文应给出明确选择。

失败应区分两种情况。格式非法的 delta 不进入增量候选；
合法变更缺少连续版本或增量证明时，可以重新读取当前完整快照计算。
若来源 mutation 已提交，增量元数据无效只拒绝相应候选，
不得将保留旧发布描述为源回滚。是否允许完整回退由明确错误合同决定。

**复核标准：** 给出位置映射表和代表性输入，
覆盖同位置插入、插入恰好位于检查点、删除覆盖端点、
多编辑合成、非法 UTF-8 边界和版本链断裂。
来源、样式、检查点与交互消费者使用同一映射定义，错误归属清楚。

## inline 结构与尺寸的依赖分类

**LTI-R04，P2。** 资产表把 inline 尺寸和 baseline 列入行布局输入，
但 inline 的存在、顺序及插入位置也可能改变 shaping 的 run 边界。
Parley 0.7.0 的 shaping 会在 inline box 的插入位置断开 run，
不能把所有 inline 更新都归为重新换行。[cite:3](#source-3)

母方案和 ADR-042 已要求保留结构身份与跨节点上下文；
此意见要求细化本提案的依赖表，不将已有整体要求视为缺失。
修订应明确：新增、删除、移动 inline 盒或边框占位标记，
进入分析及 shaping 边界的重新验证；仅尺寸或 baseline 改变，
在引擎声明可分离且结构未变时尝试复用 shaping。
实际测量反馈若同时改变贡献结构，应按更广依赖范围重新计算。

**复核标准：** 依赖表分别列出结构变化与纯度量变化，
验证计划覆盖同样文字在不同位置插入 inline 盒、
盒移除后文字重新相邻，以及仅尺寸改变的宽度复用。
使用已确认相关 features 的字体比较完整结果，不能预设任何字体必然产生连字。

## 全段成本与端到端验收

**LTI-R05，P2。** 初期保留全段 bidi 分析时，局部 shaping 仍可能支付全段读取成本。
Parley 的 bidi resolver 即使进入无需复杂 bidi 的路径，也先遍历输入并建立相关状态。
连续段落入口还可能在每次新版本上物化整个变更段落。
按版本复用可以避免同版本重复复制，无法自动消除不同版本间的整段物化。
这些成本不等于局部 shaping 窗口大小。[cite:4](#source-4)

现有复杂度表将 K 定义为必须重新分析的内容，未发现形式上的复杂度错误。
修订重点是避免把阶段 O(K) 当作完整编辑路径的工作量或时间。
建议分别记录全段分析字节、物化字节、实际 shaping cluster、
换行扫描量，以及导出、验证和发布成本；累计工作与去重输入规模分别标注。
额外 shaping 和回退前已完成的工作同样计入。

巨段目标应在这些成本下限测出后按输入和引擎能力冻结。
保留原 Large 的 p95 ≤ 16 ms 与固定可见区查询及 IR p95 ≤ 4 ms 目标，
不得用局部阶段达标关闭端到端目标，也不能用 worker 响应性代替 CPU 完成延迟。

**复核标准：** 性能协议能分辨全段分析、物化和局部 shaping 的成本，
报告连续编辑中各阶段实际工作量、扩张次数与退化比例。
随机等价通过、缓存命中或局部阶段变快均不能单独关闭性能验收。
本次没有新增采样，不给出新的耗时或提速预测。
