# Novadraw 品牌命名研究

类型：`proposal`

状态：`discussion`

更新日期：2026-10-06

## 1. 文档目的

本文记录 Novadraw 品牌名的阶段性讨论、外部占用调查、候选方向和后续筛选方法，
便于继续研究。本文不是品牌决策，不触发仓库、crate、公开 API、文档术语或产品名
重命名。

在正式决策和迁移计划获批前：

- 项目、框架和主 crate 的规范名称仍为 `Novadraw`；
- 展示名称可统一写作 `NovaDraw`，代码、crate 和路径继续使用 `novadraw`；
- `Weft`、`Heddle` 及本文出现的其他名称都只是候选或语义素材；
- 不因候选品牌调整架构术语、模块职责或公开 API。

## 2. 当前结论

`Novadraw` 的问题主要是品牌记忆度和定位宽度，而不是搜索唯一性：

- `Nova` 与 `Draw` 都是高频通用词，组合后容易被理解为普通绘图应用；
- `Draw` 强调绘制动作，不能完整表达 Figure、Layout、Connection、Event、
  Animation、Editor 和多后端共同组成的框架；
- 名称含义直观、拼写简单，且当前没有发现强势的同名 Rust 图形框架；
- 现有代码、crate、文档和验证证据已经广泛使用该名称，迁移具有实际成本。

因此，当前不应为了“听起来更新”而替换名称。新名称必须在品牌独特性、范围承载力、
发音、搜索占用和生态扩展方面显著优于 `Novadraw`，才能证明迁移合理。

阶段性建议分为两条路线：

1. **低成本优化**：保留 `novadraw` 技术标识，展示名称统一为 `NovaDraw`，配合稳定的
   产品描述与视觉识别。
2. **战略性重命名**：为整个 Core、Editor、Inspector、Text 和 backend 生态选择一个
   可独占的原创母品牌，再制定一次性迁移计划。

## 3. 当前品牌评估

| 维度 | 评价 | 说明 |
|---|---|---|
| 含义清晰度 | 高 | 可以直接联想到绘图能力 |
| 搜索辨识度 | 较高 | 精确名称当前公开结果较少 |
| 品牌记忆度 | 中 | 两个通用词组合，缺少独特语义锚点 |
| 框架承载力 | 中低 | 容易被误解为绘图工具，而不是可扩展图形与编辑框架 |
| 发音与拼写 | 高 | 中英文开发者均较容易复述 |
| 迁移成本 | 高 | 2026-10-06 快照中，约 505 个 Git 跟踪文件包含该名称 |

当前可使用的定位语句：

> NovaDraw is a composable graphics framework for Rust.

中文可表达为：

> NovaDraw 是面向 Rust 的可组合图形框架。

这比仅使用 “drawing engine” 更接近项目已经形成的能力边界。

## 4. `Weft` 方向

### 4.1 语义价值

`weft` 是在固定经线之间穿行并形成织物图案的纬线。该意象适合表达：

- Figure、布局、事件、动画和渲染能力相互组合；
- Core 契约保持稳定，不同策略和后端穿插其中；
- 多个独立系统最终形成一致的可见结果。

与 `Novadraw` 相比，`Weft` 更能表达组合和系统性，也不会把产品直接限制为绘图应用。

### 4.2 语义限制

`weft` 只是织物中的一组线，不是织机、编织过程或最终织物。将其作为整个框架名称，
需要额外的品牌叙事才能说明它为何代表完整系统。

此外，该词存在以下传播问题：

- 英语词尾 `/ft/` 对部分中文使用者不容易准确发音和听写；
- 它是常用字典词，搜索结果天然混有纺织内容；
- 单独看到名称时，开发者无法直接判断它属于图形框架。

### 4.3 公开占用

截至 2026-10-06，裸名称 `Weft` 不是干净的公开命名空间：

- crates.io 的 [`weft`](https://crates.io/crates/weft) 已用于 HTML 模板库；
- [`Weft`](https://weftproject.dev/) 已被一个面向 Agent、通信和运维的编程语言使用；
- npm 存在 [`@spaceteams/weft`](https://www.npmjs.com/package/@spaceteams/weft)
  计算图项目；
- crates.io 还有 `weft-core`、`weft-lang`、`weft-client` 等多个活跃名称。

因此，`Weft` 可以保留为品牌语义方向，但目前不建议直接作为裸主品牌或主 crate 名。

## 5. `Heddle` 方向

### 5.1 语义价值

heddle 是织机中引导并抬升经线、形成梭子通道的部件。若文字子系统负责字体发现、
fallback、shaping、glyph 定位、测量和轮廓准备，该意象可以表达“选择并组织离散元素，
形成可绘制结构”。

因此它更适合作为完整文字管线的概念名，例如 `Heddle Text Engine`，而不是仅指字体
文件、字体类型或 rasterizer。

### 5.2 语义与传播限制

- 大多数开发者不了解 heddle 的含义，名称不能自行说明模块职责；
- heddle 直接控制的是经线，而不是字体或字形，映射仍然需要解释；
- 若公开模块都采用织造术语，调用者会难以从名称判断功能，降低 API 可发现性。

即使使用该意象，公开 crate 和模块仍宜采用 `<brand>-text`、`text`、`font` 等描述性
名称；`Heddle` 更适合作为文档标题、内部代号或产品层名称。

### 5.3 公开占用

截至 2026-10-06：

- crates.io 的 [`heddle`](https://crates.io/crates/heddle) 已被一个开发中的 GPU
  终端项目注册，并明确声明该版本用于保留名称；
- crates.io 存在一组活跃的 `heddle-*` crate，用于 AI-native 版本控制系统；
- 同一产品族同时使用 `Heddle` 与 `Weft` 相关名称，两者组合也不能形成有效区分；
- .NET 生态存在名为
  [`Heddle`](https://www.nuget.org/packages/Heddle.Tool.win-x64) 的文本模板引擎。

因此，`Weft + Heddle` 虽然语义体系完整，但作为公开产品组合存在较强的直接碰撞。

## 6. 命名策略

### 6.1 先定义命名对象

后续讨论必须区分：

1. **母品牌**：覆盖 Core、Editor、Inspector、平台适配和未来产品；
2. **框架名称**：开发者安装和引用的技术产品；
3. **crate 名**：受 crates.io 唯一性与 Rust 命名习惯约束；
4. **子系统名称**：Text、Animation、Editor 等功能边界；
5. **产品名称**：建立在框架之上的 Studio 或领域编辑器。

不能用一个有趣的子系统隐喻直接替代母品牌设计。

### 6.2 候选名生成原则

优先寻找原创词或低频组合词，并满足：

- 2 至 3 个音节；
- 听到后基本可以拼写；
- 中英文环境均可稳定发音；
- 不使用难以口头区分的连续辅音；
- 不把范围锁死在 draw、canvas、render 或 graph；
- 能自然扩展为 `<brand>-editor`、`<brand>-text` 和 `<brand>-backend-vello`；
- 不与活跃的图形、UI、Rust、WASM、字体或开发工具项目近似。

织造、组合、结构、关系、运动和精确性可以作为语义母题，但不要求候选名称直接采用
对应的英语字典词。

### 6.3 硬性淘汰门槛

每个候选至少检查：

1. crates.io 精确名称及常用前后缀；
2. GitHub 仓库、组织和活跃项目；
3. npm、PyPI、NuGet 等邻近开发生态；
4. 主流搜索引擎中的精确名称和近似拼写；
5. 可用域名及常见社交账号；
6. 中国、美国和欧盟主要商标数据库中的软件及邻近类别；
7. 中文音译、负面含义、常见误读和听写错误。

公开搜索只能用于初筛，不能替代正式商标检索或法律意见。

### 6.4 评分方法

通过硬性门槛的候选按以下维度评分，每项 1 至 5 分：

| 维度 | 权重 |
|---|---:|
| 独特性与可搜索性 | 25% |
| 对完整产品边界的承载力 | 20% |
| 发音、拼写与跨语言传播 | 20% |
| 与项目价值主张的关联 | 15% |
| crate、域名与商标可获得性 | 15% |
| 视觉识别潜力 | 5% |

任何候选即使总分较高，只要未通过名称占用或法律门槛，也不能进入最终名单。

## 7. 品牌架构建议

无论最终母品牌为何，技术名称应保持可发现性：

```text
<Brand>
├── <brand>                 # Core
├── <brand>-editor
├── <brand>-inspector
├── <brand>-backend-vello
├── <brand>-platform-winit
└── <brand>-platform-web
```

文字、动画、布局等 Core 能力优先作为描述性模块，而不是拆成只有隐喻名称的公开
crate。品牌可以富有意象，API 与包名仍应直接表达职责。

## 8. 重命名决策门槛

只有同时满足以下条件，才进入正式重命名：

- 新名称明显优于 `Novadraw`，而非风格上的横向替换；
- 母品牌和核心 crate 的命名空间可获得；
- 已完成基础商标冲突筛查；
- 已定义展示名、代码标识、crate 前缀和子产品命名规则；
- 已评估文档链接、Cargo package、源码路径、测试 suite、发布记录和历史证据的迁移；
- 已决定旧名称是否需要兼容期，以及兼容期的唯一结束条件。

重命名获批后应形成独立迁移计划。品牌讨论本身不修改架构 ADR，也不重写历史验证
记录中的原始名称。

## 9. 后续研究问题

下一轮讨论需要依次回答：

1. 主品牌面向的是纯开源框架、商业 SDK，还是未来包含 Studio 的产品家族？
2. 希望名称首先传达“图形”“组合”“关系编辑”还是“精确基础设施”？
3. 是否保留 `Nova` 作为历史连续性，还是接受完全独立的新词？
4. 是否需要可注册的 `.com`，还是项目主页与 crates.io 身份已经足够？
5. 中文传播使用英文原名、音译名，还是独立中文名？

这些问题确认后，再按“生成候选池 → 硬门槛淘汰 → 加权评分 → 小范围记忆测试 →
商标核验”的顺序推进，不在讨论早期锁定单一名称。

## 10. 调研记录

### 2026-10-06

- 识别到 `Novadraw` 搜索唯一性尚可，但品牌记忆度和框架承载力有限；
- 讨论 `Weft` 作为框架名、`Heddle` 作为文字系统名的可能性；
- 确认两者具有较好的织造语义联系；
- 确认两者的裸 crate 名均已占用，且 Rust 生态已有同时使用 Heddle 与 Weft 的产品族；
- 暂不采纳 `Weft + Heddle` 作为公开品牌组合；
- 当前规范名称继续使用 `Novadraw`，等待系统候选筛选。
