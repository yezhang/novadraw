# 文本增量排版与可见绘制提案

类型：`proposal`

日期：2026-10-27。状态：待评审，未授权实施。

本提案细化[长文本方案修订 2](long-text-performance-proposal.md)的后续方向，
不替代其整体等待、预算准入和精确／渐进模式合同。
已接受的行为仍以 ADR-042、ADR-051 和[文字布局规范](text-layout.md)为准。
本次从需求、第四轮测量与外部源码推导，未重新扫描 Novadraw Rust 实现。
源码事实集中在[Lapce 与 Xi 参考](../../reference/lapce-text-engine.md)，
下文类型和能力均为设计角色，尚不是公开 API。

## 优先处理真实瓶颈

第四轮已减少测量时重复生成绘制和交互数据。
继续提高段落缓存命中率，无法消除一个变更巨段的完整排版成本。
后续需让编辑范围进入排版算法，同时让绘制输出随真实可见字形收缩。
Rope 支持来源存储与变化表达，shaping、换行和 GPU 输出各有自己的边界。

| 场景 | 最新 CPU 证据 | 后续重点 |
|---|---|---|
| 原 Large 固定追加 | p50 15.302 ms，p95 19.214 ms；Flow 构建自身平均 7.695 ms | 来源捕获、局部几何、校验及发布成本 |
| 51200 字节单段 | 追加 p95 38.526 ms；styled layout 平均 33.029 ms | 巨段安全增量与排版阶段拆分 |
| 51200 字节 NoWrap 长行 | 追加 p95 52.733 ms；styled layout 平均 46.507 ms | 安全增量 shaping、横向视觉索引 |
| 原 Large resize | p95 42.062 ms；新增 shaping 6 次 | 宽度变化复用 shaping |
| 原 Large resize 后录制 | p95 5.748 ms；51233 个 native glyph | 原生字形覆盖证书与可见 IR |

数据来自[第四轮实施记录](../../verification/reviews/long-text-performance-implementation-2026-10-27.md)。
每组两版各有 1000 次热样本和 200 个新进程，外部负载未受控，
部分会话及 p99 回退。平均阶段耗时、p95 和 glyph 数分别描述不同成本，
不能相加推导帧率；styled layout 当前计时也没有隔离其中的各个阶段。
本提案不给未经实测的提速倍数。

## 从来源 delta 到派生 delta

建议让来源 provider 提供不可变版本和显式变更范围。
一次变更至少包含来源身份、旧版本、新版本、旧 UTF-8 范围、
替换内容的共享切片，以及样式和 inline 依赖变化。
多个编辑以旧版本坐标解释并校验顺序、重叠及长度，不能把新偏移误当成旧偏移。

变更必须通过统一 typed mutation／通知协议到达 Runtime。
默认文字 Figure 和第三方来源使用同一能力；
只有已经声明完整变更合同的 provider 可进入局部路径。
普通 String 或只提供整值替换的来源继续使用完整计算。
不由 Runtime 猜测外部 contributor 的纯度，不用未验证的局部 hash 代替内容证据。

```mermaid
flowchart LR
    S["来源快照与 delta"] --> A["受检 shaping 资产"]
    A --> L["精确行布局快照"]
    L --> G["尺寸与交互几何"]
    L --> P["可见字形与 paint"]
```

图中各资产采用同一来源与依赖版本；两条输出分支经 Runtime 同次校验发布。
改变宽度时可复用已获证明的 shaping 资产，
改变 viewport 时查询已发布布局和墨迹，不重新排版。

来源模型可选择 Rope 或 piece tree，Core 消费共享只读切片，
不复制一份可编辑文档，也不接管 Editor CommandStack 或 undo。
Figure 来源身份、生命周期和跨节点样式组合仍保留。
Rope 的物理叶子不得成为段落、字体 run 或 shaping 的语义边界。

派生阶段依次产生分析范围、shaping 资产变化、行结果变化、位置变化及绘制失效。
增量结果必须与同版本完整计算相同。
固定区间之外也可能受影响，实际变化按算法依赖扩展；
增量传播到硬段落末尾甚至全文均是合法退化。
Lapce 的 delta 与 Xi 的派生 breaks 提供这条路径的依据，
它们没有给出可直接替换当前 TextFlow 的统一合同。

若排版入口仍要求连续段落文本，共享切片需在当前段落局部物化，
并按版本复用物化结果。必须记录这部分实际复制字节，
避免来源采用 Rope 后又在每次查询中拼出整篇 String。
外部 provider 没有不可变版本合同的部分仍重读，
不能因优化复制而跳过其 callback 或依赖观察。

## 分离 shaping 与换行

建议为文字引擎增加可选的分阶段能力，输入和输出保持 backend-neutral。
按影响拆分三类资产：

| 资产 | 主要输入 | 可复用条件 |
|---|---|---|
| 段落分析与 shaping | 文本、script/bidi、字体实例与 fallback、语言、变体、features、必要上下文 | 当前引擎声明精确复用；单纯宽度变化不影响这些输出 |
| 行布局 | shaping 资产、宽度、wrap、alignment、tabs、行距、inline 尺寸和 baseline | 全部行输入一致或有受检增量 |
| paint 与墨迹 | glyph 位置、颜色、轮廓 provider、描边、效果、clip/transform | 布局身份和实际绘制依赖一致 |

默认 Parley 和外部引擎共用同一能力发现、受检输出与失败通道。
不声明分离合同的引擎继续完整布局，宽度仍进入完整 request key。
引擎可以明确声明颜色只影响 paint；未知引擎仍保留颜色等完整输入，
不能将 paint-only 判断硬编码给默认引擎。

现有 Parley 已有对完成分析的 Layout 重新换行的 API，这是 LT-04 的可行入口。
适配层需要保留私有分析资产，并生成与现有 TextLayout 一致的不可变行结果。
break_next 的逐行能力不等于整个 shaping 可暂停，也不保证 NoWrap 巨行的单步很短。
实施前必须分别测量文本分析、fallback、shaping、换行、导出、验证及内嵌测量，
确认 33～47 ms 的 styled layout 中可复用的部分。

宽度变化还可能改变真实 inline Figure 的测量结果；
行布局需要重新读取这些依赖，必要时重新稳定化。
最先验证无内嵌、同一文本在多宽度下的分离路径，再扩大到真实混排。
不得缓存 mutable Parley Layout 给多个已发布快照共同改写。

## 在安全边界内增量 shaping

建议先保留全段 bidi 分析，试验带完整上下文的局部 shaping。
按编辑范围找到旧资产候选边界，重塑形新片段，再检查新、旧两侧的拼接证据。
只在字体实例、script、direction、language、features、fallback 及上下文合同一致时复用。
必要时向两端扩大，无法证明时回退整段。

HarfRust 现有 `unsafe_to_concat` 是可用的底层线索，
但必须在 shaping 时开启对应标志并保留证据；
仅检查旧 glyph 或仅检查 `unsafe_to_break` 都不充分。
Parley 当前公共结果没有直接提供这份证明，
需要先确认适配器或上游的扩展路径及对外交付边界。
该证明不能自动证明 bidi 和字体选择不受编辑影响。

ASCII／等宽的简化算法也只通过引擎能力声明启用。
必须覆盖实际字体 features、kerning、ligature、tabs、fallback 和数字处理，
不能以文本只含 ASCII 推导固定 advance，更不能按字符平均宽度替换精确排版。
任意第三方字体引擎能声明同样的合同，也能明确拒绝。

NoWrap 巨行不会因“增量换行”变快；其突破口是局部 shaping、
共享 glyph 片段及位置前缀度量。首次分析仍需读取必要输入，
最坏编辑可能使全段方向或 shaping 依赖失效。
本项只承诺正确的局部路径和明确退化，不承诺所有巨段编辑都达到 16 ms。

## 换行从检查点重算到状态收敛

建议将换行结果存成独立的不可变行资产，并在受检边界保存检查点。
检查点包含源位置、分析／shaping 身份、换行候选上下文、字体与 inline 依赖、
当前宽度及行策略、必要的 tab／空白状态和位置度量。
编辑后从算法证明有效的前置检查点开始，而不固定退回两个视觉行。

复用旧后缀需同时满足：

- 新旧源位置经 delta 映射后对应，未变后缀的内容和依赖有效。
- 断行位置相同，下一步换行的全部输入状态相同。
- 行级 bidi、baseline、line height、inline 与边框上下文一致。
- 全局 y 差异通过位置投影表达，旧局部 glyph 与交互资产保持不可变。

Xi 的“匹配一个后续断点即可停止”启发了这个算法，
TextFlow 还需检查复杂文字和图文混排的完整状态。
如果只有断点相同而状态不同，继续计算。
首次布局、全局宽度改变和全段字体变化通常需要遍历相关内容；
无收敛时退化到段末，不省略最终精确结果。

## 用摘要维护位置，保留墨迹索引

来源树可聚合字节数、UTF-16 单位数、硬换行与 difficulty 标志；
布局树可聚合视觉行数、精确高度、已测最大宽度和受检资产身份。
单段高度变化更新祖先摘要，通过前缀查询求后续 origin，
减少每次更新复制全部后续位置记录的需要。

变量行高必须来自精确行结果，不能套用 Lapce 的统一行高近似。
如果只测了可见行，最大宽度和总高度只能标为覆盖内精确或估算，
不能进入精确 TextFlow 的全文尺寸合同。
将整数摘要的结合律迁移到浮点高度时，需要固定聚合顺序、
误差与溢出检查，并与完整布局对照；不能默认 f64 加法严格满足结合律。

布局高度摘要只支持正常流位置查询。
实际 ink、负 bearing、跨行描边和外部轮廓仍用保守重叠包络索引。
不因正常流在屏外便跳过它可能画进 viewport 的墨迹。
RTL 长行的横向查询按视觉区间组织，结果保持原始绘制顺序，
不假定 source offset 或 glyph x 总是单调。

先用已有数组和索引做隔离原型，证明更新及复制成本后再选持久 B-tree。
不要把 Floem、Lapce 或整套 Xi 编辑器依赖加入 Core。
持久结构的旧版本留存需要计入内存预算；树高小不代表总物理占用小。

下表是算法目标及条件，均不构成本次实测结论。
N 为全文长度，K 为必须重新分析的内容，L 为需重算的视觉行，
V 为可见输出，C 为重叠包络候选数：

| 操作 | 期望工作量 | 必须保留的最坏情况 |
|---|---|---|
| Rope 局部替换 | 树路径、替换内容读取及局部节点重建 | 大范围替换仍需读取相应内容 |
| 增量 shaping | O(K) 加索引／边界查找 | K 可扩大为 N |
| 增量换行 | 被扫描 cluster 与 L 的输出 | 无收敛时计算到段末 |
| 持久高度更新 | 变化行与祖先路径 | 真实父布局或路由依赖仍可传播到更大范围 |
| 可见 IR | 索引访问、C 检查与 V 输出 | 墨迹重叠或范围未知时全扫描／完整输出 |

## 可见字形输出与局部重绘

生产绘制优先完成[原生覆盖边界](long-text-native-coverage-boundary.md)评审：
由实际字体实例、glyph、f32 转换、描边与变换定义保守覆盖，
在同次受检发布中安装包络、索引和 paint 资产。
未知覆盖仍完整输出，不用 line box 或 advance 当墨迹证书。

通过证书后，先按段落／行筛选，再按长行的视觉 glyph 区间筛选。
IR 只引用可见共享片段，允许筛选形成多个不连续范围；
各范围保持绘制顺序和原点，不重新 shaping。
缩小单个命令的 glyph 数与合并命令分别度量，
合并只跨完全相容的字体、变体、brush、clip、transform、描边与绘制状态。
不能越过具有覆盖关系的其他绘制操作重排。

后续可借鉴 Xi 的部分有效性，将文本墨迹、selection、caret 和装饰失效分开。
它们仍属于同一来源与布局版本，走引擎统一 damage／绘制顺序，
不引入示例私有 overlay，也不承诺 backend 已具备 retained line cache。
光标改变先证明不触发 shaping、来源几何和全文 glyph 复制，
再决定是否需要后端缓存；仅加 clip 而 CPU 仍导出全文，不算可见 IR 完成。

局部资产复用仍须经过完整发布批次的依赖验证。
边框首尾、selection geometry、inline placement、paint 包络与索引
对应同次受检结果；准备失败保留旧发布，不把已提交源变更声称为回滚。
只有证明不变的资产可以跳过重复验证，
不能为了局部路径绕开现有 Runtime、parent-child 或路由检查。

## 调度与字体后端

异步工作承接 LT-05，以不可变输入在 worker 独立上下文计算。
结果带 Runtime 生命周期、request generation、文本／宽度／字体版本与所有外部依赖，
回到 Runtime 的提交点统一检查、校验和发布。
Lapce 的 syntax revision 检查只提供最小参考，排版检查范围更宽。

精确模式继续整体等待，后台候选未就绪时保留旧完整发布；
字体上下文、任务队列、被取消输出和旧快照都计入预算。
保留有限合并、公平性和终态恢复，不能靠不断丢弃结果掩盖不收敛。
渐进覆盖与估算滚动范围属于 LT-06 独立合同，
未就绪区域不产生虚构的 caret、hit 或 accessibility 几何。
异步降低 UI 阻塞，不自动降低 CPU 完成延迟，也不能替代安全巨段分步。

字体先评估相同实例的资源解析、outline 准备及上传是否重复。
仅当可见 IR 收口后 GPU／编码仍是主要瓶颈，才推进 LT-08 atlas 试验。
缓存键覆盖字体内容版本、变体、glyph、ppem、DPI、subpixel、AA 与 synthesis；
设备重置失效，任意变换和大字号有明确回退。
atlas 不改变布局 advance 或交互结果，不能假定 Lapce 的 Cosmic Text 路径
对 Vello 更快。

## 建议的评审与实施顺序

以下均为待评审工作包，只映射既有 LT 编号，不建立第二份执行队列：

| 顺序 | 工作包 | 对应切片 | 可评审结果 |
|---|---|---|---|
| 优先 | styled layout 分阶段计时、导出／复制归属及外部能力合同 | LT-00、LT-04 | 判断 shaping、换行和结果导出的真实占比 |
| 优先 | 原生覆盖证书与横向／纵向可见 IR | LT-03 | 有限输入 Full/Partial 对照及可见输出计数 |
| 随后 | 可选 shaping／换行分离，宽度变化复用 | LT-04 | 多宽度结果与完整布局等价，记录真实内嵌反馈 |
| 随后 | source delta、共享切片、安全局部 shaping 与换行检查点 | LT-04、LT-07 的来源部分 | 长段／长行局部编辑等价，最坏退化明确 |
| 按证据推进 | 持久高度／宽度摘要和局部位置发布 | LT-02、LT-07 | 后续位置复制减少，交互和墨迹一致 |
| 独立评审 | worker、渐进覆盖及 glyph atlas | LT-05、LT-06、LT-08 | 调度、预算、产品交互与设备生命周期 |

建议先把分阶段合同和原生可见输出做实，再扩大到安全巨段增量。
紧凑来源可先试验 delta／共享片段，完整海量文档 provider 不必提前进入首批。
引擎无法提供安全 shaping 证据时，仍可交付宽度变化复用和可见绘制，
巨段编辑的同步目标保留未达状态。

## 验证与成本门禁

正确性用同输入的完整计算作 oracle，比较文本来源、glyph/font/advance/offset、
行断点、视觉顺序、尺寸、inline placement、caret／selection 和实际像素。
除随机编辑外，明确覆盖跨节点连字、Arabic joining、方向控制、组合字符、
emoji ZWJ／regional indicator、CJK／Thai breaking、tabs、跨字体和宽度反馈。
失败、字体替换、来源删除、旧快照留存与不具备增量能力的外部引擎同样覆盖。
随机反例固化为可复现输入，不只比较截图。

性能继续保留现有四个工厂、固定追加和完整独立会话分布。
增加段首／段中／段末替换、连续增长、分裂／合并段落、长行横向滚动、
多宽度和真实图文混排；逐次记录实际重算字节／cluster／行数、复制字节、
共享与留存分配、校验／发布、IR 与 GPU／present。
局部操作要报告扫描窗口与退化比例，不能只报告缓存命中或平均时间。
原 Large CPU 追加 p95 ≤ 16 ms、固定可见区查询及 IR p95 ≤ 4 ms 目标不变，
巨段目标按能力和输入另行冻结，不套用 Xi 的历史 40 µs。

源 delta 与索引原则上可用现有依赖实现；分阶段适配增加资产和元数据，
Rope 增加路径副本，worker 可能复制字体上下文，atlas 增加纹理与上传。
依赖引入、Native release、Web Wasm／JS／字体及实际压缩传输、
首次加载和 worker 初始化需要同配置启用／禁用测量。
当前没有这些增量的产物或运行数据，体积收益和延迟收益均待采证。

涉及 `text.flow`、`text.interaction`、`graphics.context`、`paint.protocol`、
`damage.repaint` 和 `render.backend_session` 时，
按[API 语义账本](../../parity/draw2d/api-coverage.md)逐项核对。
新增分阶段、delta、检查点或发布合同须有最小 ADR 与外部消费者证明，
获批后才登记 [P2 backlog](../../roadmap/p2-delta-backlog.md) 的单一 Execute 切片。
