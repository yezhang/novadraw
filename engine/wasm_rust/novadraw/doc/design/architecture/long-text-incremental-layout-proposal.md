# 文本增量排版与可见绘制提案

类型：`proposal`

日期：2026-10-27。修订：2。状态：已补齐设计响应，待复核，未授权实施。

本轮采用[审计意见](../../verification/reviews/long-text-incremental-layout-review-2026-10-27.md)
LTI-R01～R05。固定审计基线保持不变；正文补齐拼接证明、检查点恢复、
delta 映射、inline 依赖和完整成本口径。设计响应不代表意见已关闭或算法已通过验证。

本提案细化[长文本方案修订 2](long-text-performance-proposal.md)的后续方向，
不替代其整体等待、预算准入和精确／渐进模式合同。
已接受的行为仍以 ADR-042、ADR-051 和[文字布局规范](text-layout.md)为准。
本次从需求、第四轮测量与外部源码推导，未重新扫描 Novadraw Rust 实现。
源码事实集中在[Lapce 与 Xi 参考](../../reference/lapce-text-engine.md)，
下文类型和能力均为设计角色，尚不是公开 API。

## 优先处理真实瓶颈

第四轮已减少测量时重复生成绘制和交互数据。
继续提高段落缓存命中率，无法消除一个变更巨段的完整排版成本。
后续需让编辑范围进入排版算法，同时让绘制输出随真实可见字形收缩。
Rope 支持来源存储与变化表达，shaping、换行和 GPU 输出各有自己的边界。

| 场景 | 最新 CPU 证据 | 后续重点 |
|---|---|---|
| 原 Large 固定追加 | p50 15.302 ms，p95 19.214 ms；Flow 构建自身平均 7.695 ms | 来源捕获、局部几何、校验及发布成本 |
| 51200 字节单段 | 追加 p95 38.526 ms；styled layout 平均 33.029 ms | 巨段安全增量与排版阶段拆分 |
| 51200 字节 NoWrap 长行 | 追加 p95 52.733 ms；styled layout 平均 46.507 ms | 安全增量 shaping、横向视觉索引 |
| 原 Large resize | p95 42.062 ms；新增 shaping 6 次 | 宽度变化复用 shaping |
| 原 Large resize 后录制 | p95 5.748 ms；51233 个 native glyph | 原生字形覆盖证书与可见 IR |

数据来自[第四轮实施记录](../../verification/reviews/long-text-performance-implementation-2026-10-27.md)。
每组两版各有 1000 次热样本和 200 个新进程，外部负载未受控，
部分会话及 p99 回退。平均阶段耗时、p95 和 glyph 数分别描述不同成本，
不能相加推导帧率；styled layout 当前计时也没有隔离其中的各个阶段。
本提案不给未经实测的提速倍数。

## 从来源 delta 到派生 delta

建议让来源 provider 提供不可变版本和显式变更范围。
一次变更至少包含来源身份、旧版本、新版本、旧 UTF-8 范围、
替换内容的共享切片，以及样式和 inline 依赖变化。
多个编辑以旧版本坐标解释并校验顺序、重叠及长度，不能把新偏移误当成旧偏移。

### delta 的规范输入与位置映射

单个 delta 以同一来源旧快照为坐标基准，替换区间采用半开区间 `[a,b)`，
空区间表示插入。端点必须位于合法 UTF-8 code point 边界；
它只证明编码合法，不证明 grapheme、shaping 或检查点边界有效。
校验来源 namespace／代次、旧新版本、旧范围长度、替换 UTF-8 和最终长度，
所有长度、累计位移和区间加法使用受检整数，溢出时拒绝。

选择以下确定的规范形式，消除同一坐标的操作歧义：

- 非空替换区间按旧起点排序，禁止重叠。相邻非空区间要求 provider 先合并，
  保留替换内容与各来源映射；本能力不隐式猜测合并顺序。
- 同位置的多个纯插入按 payload 中唯一的 `insertion_order` 升序拼接，
  得到一个插入组。顺序字段缺失、重复或不符合声明时拒绝。
- 插入位于非空替换区间内部或任一端点时，要求 provider 将它并入该替换，
  并提交唯一的替换内容；本阶段拒绝未规范化的组合。
- 无内容的纯插入移除；段落边界和 inline 结构变化另带结构证据，
  不通过字符串相同推断结构未变。

位置变换带独立的 `BeforeInserted`／`AfterInserted` 偏向。
设已处理的前置编辑累计位移为 d，当前替换 `[a,b)` 的新内容长度为 m，
则其新范围为 `[a+d,a+d+m)`，映射定义如下：

| 旧位置 x | BeforeInserted | AfterInserted | 位置状态 |
|---|---|---|---|
| 当前编辑之前 | x+d | x+d | 未变 |
| 纯插入位置 x=a=b | a+d | a+d+m | 插入接缝 |
| 非空替换的起点 x=a | a+d | a+d+m | 替换接缝 |
| 非空替换内部 a<x<b | a+d | a+d+m | 原位置已删除，返回锚点及删除标记 |
| 非空替换终点 x=b | a+d+m | a+d+m | 后缀起点 |
| 当前编辑之后 | 按更新后的累计位移继续映射 | 同左 | 未变或后续编辑 |

新内容为空时两个偏向归于同一锚点，删除标记仍保留。
被删除位置不能仅凭锚点获得有效检查点或旧交互几何。
源范围与样式范围先拆成未变片段，再用同一变换映射；
新增内容的来源和样式由替换 payload 提供。端点采用何种偏向由消费者显式指定，
不能只变换两个端点便把被替换内容认定为未变范围。

位置变换偏向与 `TextAffinity::Upstream/Downstream` 属于不同语义：
前者决定编辑后落在新增内容哪一侧，后者解释当前布局中换行／bidi 等歧义位置。
交互适配器显式选择编辑偏向，并保留或重新求解当前布局 affinity；
不按同名或方向直觉自动互换。检查点偏向由其前置／后置上下文合同确定，
插入恰好落在检查点时还须重新验证状态，映射合法不代表可以恢复。

例如，`abcd` 在旧 offset 2 插入 `X`、`Y`，声明顺序 0、1，
得到 `abXYcd`，旧位置 2 映射为 2 或 4。
删除 `[1,3)` 得到 `ad`，旧位置 2 映射为 1 且标为已删除，
旧位置 3 映射为有效后缀接缝 1。
`AéB` 的 offset 2 在 UTF-8 编码内部，不能作为合法编辑端点。

### 版本链、合成与失败归属

连续 delta 要求前一项的新版本等于后一项的旧版本，
来源 namespace 和代次连续；版本不通过数值相邻或内容 hash 相同推断。
合成先按各自旧快照解释，再组合带插入顺序和删除标记的位置变换及共享片段。
不能直接把第二项区间抄进第一项坐标。无法无歧义规范化或证明范围内容对应时，
保留顺序应用，放弃组合增量；验证需比较顺序应用与合成后的最终文本和位置映射。

段落 split／merge 按母方案生成新段落 token，由捕获来源的 provider
提交旧到新段落及 source-local 范围关系，新快照拥有最终映射。
真实 Figure 身份仍按生命周期保留或退出；未声明身份迁移的来源不跨身份复用证书。
不能按段落序号补造 source 归属，不能把旧 revision 的位置直接用于新交互查询。

| 失败位置 | 处理 | 源状态与发布 |
|---|---|---|
| mutation 提交前发现非法 UTF-8、范围、顺序、身份或溢出 | 按 mutation 错误拒绝 | 尚未提交源变更 |
| 外部源已提交后发现 delta 元数据格式非法 | 拒绝该增量候选并记录诊断；完整当前快照可独立重验后完整计算 | 不回滚源；新完整候选成功前保留旧发布 |
| delta 合法但版本链断裂、证书缺失或恢复不支持 | 重读权威当前完整快照，选择完整计算 | 不宣称局部复用成立 |
| 当前完整源无法验证、预算耗尽、生命周期退出或请求过期 | 结束／拒绝当前候选，按既有错误与恢复合同处理 | 不借完整回退绕过预算，不无限重试 |

完整回退仅在来源快照自身有效、请求仍有效且预算允许时执行；
失败的增量工作仍计入同一预算。保留旧发布不表示它已对应最新源，
对外查询继续遵守现有稳定化与版本合同。

变更必须通过统一 typed mutation／通知协议到达 Runtime。
默认文字 Figure 和第三方来源使用同一能力；
只有已经声明完整变更合同的 provider 可进入局部路径。
普通 String 或只提供整值替换的来源继续使用完整计算。
不由 Runtime 猜测外部 contributor 的纯度，不用未验证的局部 hash 代替内容证据。

```mermaid
flowchart LR
    S["来源快照与 delta"] --> A["受检 shaping 资产"]
    A --> L["精确行布局快照"]
    L --> G["尺寸与交互几何"]
    L --> P["可见字形与 paint"]
```

图中各资产采用同一来源与依赖版本；两条输出分支经 Runtime 同次校验发布。
改变宽度时可复用已获证明的 shaping 资产，
改变 viewport 时查询已发布布局和墨迹，不重新排版。

来源模型可选择 Rope 或 piece tree，Core 消费共享只读切片，
不复制一份可编辑文档，也不接管 Editor CommandStack 或 undo。
Figure 来源身份、生命周期和跨节点样式组合仍保留。
Rope 的物理叶子不得成为段落、字体 run 或 shaping 的语义边界。

派生阶段依次产生分析范围、shaping 资产变化、行结果变化、位置变化及绘制失效。
增量结果必须与同版本完整计算相同。
固定区间之外也可能受影响，实际变化按算法依赖扩展；
增量传播到硬段落末尾甚至全文均是合法退化。
Lapce 的 delta 与 Xi 的派生 breaks 提供这条路径的依据，
它们没有给出可直接替换当前 TextFlow 的统一合同。

若排版入口仍要求连续段落文本，共享切片需在当前段落局部物化，
并按版本复用物化结果。必须记录这部分实际复制字节，
避免来源采用 Rope 后又在每次查询中拼出整篇 String。
外部 provider 没有不可变版本合同的部分仍重读，
不能因优化复制而跳过其 callback 或依赖观察。

## 分离 shaping 与换行

建议为文字引擎增加可选的分阶段能力，输入和输出保持 backend-neutral。
按影响拆分三类资产：

| 资产 | 主要输入 | 可复用条件 |
|---|---|---|
| 段落分析与 shaping | 文本、script/bidi、字体实例与 fallback、语言、变体、features、必要上下文；inline 盒及边框占位标记的存在、顺序、插入位置和身份 | 当前引擎声明精确复用；结构未变，单纯宽度／度量变化不影响这些输出 |
| 行布局 | shaping 资产、宽度、wrap、alignment、tabs、行距、结构未变的 inline 尺寸和 baseline | 全部行输入一致或有受检增量；度量未改变 shaping 输入 |
| paint 与墨迹 | glyph 位置、颜色、轮廓 provider、描边、效果、clip/transform | 布局身份和实际绘制依赖一致 |

默认 Parley 和外部引擎共用同一能力发现、受检输出与失败通道。
不声明分离合同的引擎继续完整布局，宽度仍进入完整 request key。
引擎可以明确声明颜色只影响 paint；未知引擎仍保留颜色等完整输入，
不能将 paint-only 判断硬编码给默认引擎。

现有 Parley 已有对完成分析的 Layout 从段首重新换行的 API，
可作为宽度复用的候选入口；它不提供跨编辑检查点恢复。
适配层需要证明如何保留私有分析资产、隔离 mutable 行结果，
并生成与现有 TextLayout 一致的不可变输出，之后才能登记为可交付能力。
break_next 的逐行能力不等于整个 shaping 可暂停，也不保证 NoWrap 巨行的单步很短。
实施前必须分别测量文本分析、fallback、shaping、换行、导出、验证及内嵌测量，
确认 33～47 ms 的 styled layout 中可复用的部分。
这些历史计时包含完整 styled layout 的多个阶段，不能直接归为 shaping；
初期全段 bidi 分析即使不需要复杂重排，也可能读取整段并建立状态。
每个新版本的连续段落物化另计，同版本复用只消除同版本重复复制，
不能证明连续编辑已消除整段复制。

宽度变化还可能改变真实 inline Figure 的测量结果；
行布局需要重新读取这些依赖，必要时重新稳定化。
新增、删除、移动 inline 盒或边框占位标记会改变结构及 shaping run 边界，
进入分析和 shaping 证书重验。纯尺寸／baseline 改变只能在引擎声明可分离、
结构和字体上下文未变时复用 shaping。
测量反馈同时改变贡献结构时，升级失效范围，不能继续按纯度量处理。
最先验证无内嵌、同一文本在多宽度下的分离路径，再扩大到真实混排。
不得缓存 mutable Parley Layout 给多个已发布快照共同改写。

## 在安全边界内增量 shaping

建议先保留全段 bidi 分析，试验带完整上下文的局部 shaping。
按编辑范围找到旧资产候选边界，重塑形新片段，再检查新、旧两侧的拼接证据。
只在字体实例、script、direction、language、features、fallback 及上下文合同一致时复用。
必要时向两端扩大，无法证明时回退整段。

HarfRust 现有 `unsafe_to_concat` 是可用的底层线索，
但必须在 shaping 时开启对应标志并保留证据；
仅检查旧 glyph 或仅检查 `unsafe_to_break` 都不充分。
Parley 当前公共结果没有直接提供这份证明，
需要先确认适配器或上游的扩展路径及对外交付边界。
该证明不能自动证明 bidi 和字体选择不受编辑影响。

### 左右拼接证据的取得与扩张

设旧段落为 T0，新段落为 T1，选取包住全部相关编辑及结构变化的旧范围 `[l,r)`。
候选端点从有 cluster 和上下文证书的边界选择，
用规范 delta 映射到新范围 `[l',r')`，并保证该范围包含全部新增内容。
包含编辑的范围左端采用 BeforeInserted、右端采用 AfterInserted；
真实接缝仍需在映射后检查 cluster 边界，失败时扩大旧范围再映射。
候选接缝的文本、字体、方向与完整上下文先经新分析验证；
删除位置、不可映射的边界或跨 identity 迁移不能直接用作接缝。

内部拼接位置必须分别有旧、重新 shaping 后的新证据。
左端检查旧左接缝及新计算片段起点；右端不直接检查最后一个 glyph，
而是把新 shaping 范围扩展到 r' 之后，使 r' 成为输出内部的 cluster 起点。
仅当该内部边界确实存在、映射对应并且拼接两侧的
`unsafe_to_concat` 证据都有效时，才截取 `[l',r')` 用于组合；
额外后缀只用于取证，不重复装入结果。证明不能用 glyph 数或最后一个 glyph 推断。
接缝按源文本 cluster 坐标定位；RTL 的视觉 glyph 顺序不能代替源边界映射。

新片段计算提供真实段落的前后上下文、相同 shaping 参数和启用的
`PRODUCE_UNSAFE_TO_CONCAT`。它采用内部片段的真实位置，
不能把切片右端伪装为段落结束。若运行接口不能提供这些上下文或内部标志，
该引擎本次使用整段路径。
抵达真实段落开头／末尾时，相应端不存在可复用外侧片段，
按新段落真实边界上下文计算该端，另一内部接缝仍须证明。
不能给未抵达真实末端的片段省略右端取证。

算法步骤如下，属于待验证设计，不表示 HarfRust 或 Parley 已提供组合 API：

```text
verify current paragraph, normalized delta, analysis and dependencies
choose old cluster boundaries enclosing every relevant change
repeat:
    map old boundaries into current paragraph; include all inserted content
    extend new right probe beyond proposed seam to an internal cluster boundary
    shape probe with true paragraph context and required flags
    verify mapped old/new evidence at every internal seam
    if seams and unchanged outside dependencies are proven:
        trim probe-only suffix; assemble immutable pieces in current coordinates
        validate complete candidate; return candidate
    move failing seam outward; never reuse an unproven seam
    if proof is unavailable or whole paragraph is reached:
        use full current paragraph computation within remaining request budget
```

每次扩张必须严格扩大被计算范围，候选边界数有限，
所有探测、额外后缀、重试及完整回退累计计费。
预算耗尽直接失败；不通过重置计数器完成回退。
若超出当前可提供上下文的字体 run，重新检查更广的字体／script／bidi 范围。
不能假定每次固定增加若干字节就能取得安全证据。
右端不存在内部 cluster、证据无法导出或新旧方向不等价时，扩大或整段重算。

验证需单列左端、内部右端、真实段落末端、跨边界连字、Arabic joining、
连续扩张及扩张后回退；与同版本完整 shaping 对照所有 glyph 和位置，
并记录探测范围、实际扫描、扩张次数和丢弃输出。

ASCII／等宽的简化算法也只通过引擎能力声明启用。
必须覆盖实际字体 features、kerning、ligature、tabs、fallback 和数字处理，
不能以文本只含 ASCII 推导固定 advance，更不能按字符平均宽度替换精确排版。
任意第三方字体引擎能声明同样的合同，也能明确拒绝。

NoWrap 巨行不会因“增量换行”变快；其突破口是局部 shaping、
共享 glyph 片段及位置前缀度量。首次分析仍需读取必要输入，
最坏编辑可能使全段方向或 shaping 依赖失效。
本项只承诺正确的局部路径和明确退化，不承诺所有巨段编辑都达到 16 ms。

## 换行从检查点重算到状态收敛

建议将换行结果存成独立的不可变行资产，并在受检边界保存检查点。
检查点包含源位置、分析／shaping 身份、换行候选上下文、字体与 inline 依赖、
当前宽度及行策略、必要的 tab／空白状态和位置度量。
编辑后从算法证明有效的前置检查点开始，而不固定退回两个视觉行。

### 默认引擎的恢复可行性

Parley 0.7.0 的公开 `revert` 只恢复上次计算前的状态；
新建 `Layout::break_lines` 从段首开始，没有公开跨编辑 export／restore 合同。
重建后从段首扫描到检查点属于完整前缀计算，不能记为检查点恢复收益。
本提案将宽度复用的完整重新换行与跨编辑恢复拆成独立能力。

默认引擎首先评估上游扩展路径：在 Parley 维护的算法内定义受检、
有格式版本的检查点 export／restore，保存完整状态并支持新资产映射。
这是一条候选路线，当前没有上游接口、补丁或可行性实验的交付证据。
需核验 state、run／cluster／item 引用、普通和 emergency 候选断点、
已提交行输出、alignment 的再处理、inline 状态及数值检查能否正确重建。
能力所有权仍在文字引擎，Core 不暴露或保存第三方内部状态字段。

仅包装当前公开 Parley API 的适配器不能凭空恢复这些私有状态。
若上游扩展不可行，再独立评审基于受检 shaping 资产的换行算法及其全量等价；
不在本轮暗中复制私有布局器或新增一条默认算法。
证据不足时，Parley 路径完整换行；外部引擎通过同一能力声明支持与否。
不可恢复不能妨碍独立验证宽度复用或可见绘制。

### 跨版本局部证书与恢复过程

区分三层身份：发布快照的当前 revision、当前整段分析资产、
可留存局部片段的不可变证书。编辑可生成新的整段分析资产，
局部复用不要求新旧整段身份相等，而要求相关局部状态经映射后等价。
相同后缀字节也不足以证明方向、字体选择和行上下文相同。

局部证书绑定被覆盖的 source 范围／身份、准确内容或可信不可变片段身份、
分析得到的 bidi／script／字体／features、结构与度量依赖、
引擎算法及检查点格式版本，以及完整后续算法状态。
散列只作查找；不能以 hash 相同替代内容和状态证明。
状态中的 run／cluster／item 下标须映射到新资产的对应片段，
不能复制旧整段的绝对下标。引擎不能表达这种等价时，证书失效。

完整过程为：

1. 在旧候选完成校验后生成检查点，连同不可变局部资产保存；
   不对临时半成品或已失败候选签发有效证书。
2. 按 delta 和结构／字体／宽度依赖标记失效范围，
   对候选前置检查点做带偏向的映射；已删除、接缝受影响或缺证据时向前扩大。
3. 用新分析结果重验被复用前缀和检查点状态，映射所有资产引用，
   由声明恢复能力的引擎构造新任务拥有的计算状态。
4. 向后计算至映射后的后缀接缝；验证断点及全部状态等价，
   将 y／全局位置差异分离成新投影，再验证旧局部后缀是否仍适用。
5. 新快照拥有当前来源映射、fragment、位置投影与交互 revision，
   可以引用已证明有效的旧不可变资产；不改写旧快照或冒充其 revision。
6. 不支持恢复、格式版本不匹配或数值／引用验证失败时完整换行；
   输入、预算或生命周期错误按候选失败处理，不反复尝试安装检查点。

检查点中的数量、位置、累计 advance／高度和候选边界须有限且不溢出，
聚合精度与完整算法保持一致。需要参与比较的每项状态都在能力合同内定义，
不能只比较断点和累计 y。移出场景、依赖更新、淘汰及引擎版本变化按证书失效处理，
旧快照的 lease 仍可留存其历史资产。

复用旧后缀需同时满足：

- 新旧源位置经 delta 映射后对应，未变后缀的内容和依赖有效。
- 断行位置相同，下一步换行的全部输入状态相同。
- 行级 bidi、baseline、line height、inline 与边框上下文一致。
- 全局 y 差异通过位置投影表达，旧局部 glyph 与交互资产保持不可变。

Xi 的“匹配一个后续断点即可停止”启发了这个算法，
TextFlow 还需检查复杂文字和图文混排的完整状态。
如果只有断点相同而状态不同，继续计算。
首次布局、全局宽度改变和全段字体变化通常需要遍历相关内容；
无收敛时退化到段末，不省略最终精确结果。
验证需覆盖断点相同但状态不同、新整段资产引用有效旧后缀、
旧快照留存、inline 反馈、格式版本不匹配与拒绝恢复的外部引擎。

## 用摘要维护位置，保留墨迹索引

来源树可聚合字节数、UTF-16 单位数、硬换行与 difficulty 标志；
布局树可聚合视觉行数、精确高度、已测最大宽度和受检资产身份。
单段高度变化更新祖先摘要，通过前缀查询求后续 origin，
减少每次更新复制全部后续位置记录的需要。

变量行高必须来自精确行结果，不能套用 Lapce 的统一行高近似。
如果只测了可见行，最大宽度和总高度只能标为覆盖内精确或估算，
不能进入精确 TextFlow 的全文尺寸合同。
将整数摘要的结合律迁移到浮点高度时，需要固定聚合顺序、
误差与溢出检查，并与完整布局对照；不能默认 f64 加法严格满足结合律。

布局高度摘要只支持正常流位置查询。
实际 ink、负 bearing、跨行描边和外部轮廓仍用保守重叠包络索引。
不因正常流在屏外便跳过它可能画进 viewport 的墨迹。
RTL 长行的横向查询按视觉区间组织，结果保持原始绘制顺序，
不假定 source offset 或 glyph x 总是单调。

先用已有数组和索引做隔离原型，证明更新及复制成本后再选持久 B-tree。
不要把 Floem、Lapce 或整套 Xi 编辑器依赖加入 Core。
持久结构的旧版本留存需要计入内存预算；树高小不代表总物理占用小。

下表是算法目标及条件，均不构成本次实测结论。
N 为全文长度，K 为必须重新分析的内容，L 为需重算的视觉行，
V 为可见输出，C 为重叠包络候选数：

| 操作 | 期望工作量 | 必须保留的最坏情况 |
|---|---|---|
| Rope 局部替换 | 树路径、替换内容读取及局部节点重建 | 大范围替换仍需读取相应内容 |
| 增量 shaping | O(K) 加索引／边界查找 | K 可扩大为 N |
| 增量换行 | 被扫描 cluster 与 L 的输出 | 无收敛时计算到段末 |
| 持久高度更新 | 变化行与祖先路径 | 真实父布局或路由依赖仍可传播到更大范围 |
| 可见 IR | 索引访问、C 检查与 V 输出 | 墨迹重叠或范围未知时全扫描／完整输出 |

## 可见字形输出与局部重绘

生产绘制优先完成[原生覆盖边界](long-text-native-coverage-boundary.md)评审：
由实际字体实例、glyph、f32 转换、描边与变换定义保守覆盖，
在同次受检发布中安装包络、索引和 paint 资产。
未知覆盖仍完整输出，不用 line box 或 advance 当墨迹证书。

通过证书后，先按段落／行筛选，再按长行的视觉 glyph 区间筛选。
IR 只引用可见共享片段，允许筛选形成多个不连续范围；
各范围保持绘制顺序和原点，不重新 shaping。
缩小单个命令的 glyph 数与合并命令分别度量，
合并只跨完全相容的字体、变体、brush、clip、transform、描边与绘制状态。
不能越过具有覆盖关系的其他绘制操作重排。

后续可借鉴 Xi 的部分有效性，将文本墨迹、selection、caret 和装饰失效分开。
它们仍属于同一来源与布局版本，走引擎统一 damage／绘制顺序，
不引入示例私有 overlay，也不承诺 backend 已具备 retained line cache。
光标改变先证明不触发 shaping、来源几何和全文 glyph 复制，
再决定是否需要后端缓存；仅加 clip 而 CPU 仍导出全文，不算可见 IR 完成。

局部资产复用仍须经过完整发布批次的依赖验证。
边框首尾、selection geometry、inline placement、paint 包络与索引
对应同次受检结果；准备失败保留旧发布，不把已提交源变更声称为回滚。
只有证明不变的资产可以跳过重复验证，
不能为了局部路径绕开现有 Runtime、parent-child 或路由检查。

## 调度与字体后端

异步工作承接 LT-05，以不可变输入在 worker 独立上下文计算。
结果带 Runtime 生命周期、request generation、文本／宽度／字体版本与所有外部依赖，
回到 Runtime 的提交点统一检查、校验和发布。
Lapce 的 syntax revision 检查只提供最小参考，排版检查范围更宽。

精确模式继续整体等待，后台候选未就绪时保留旧完整发布；
字体上下文、任务队列、被取消输出和旧快照都计入预算。
保留有限合并、公平性和终态恢复，不能靠不断丢弃结果掩盖不收敛。
渐进覆盖与估算滚动范围属于 LT-06 独立合同，
未就绪区域不产生虚构的 caret、hit 或 accessibility 几何。
异步降低 UI 阻塞，不自动降低 CPU 完成延迟，也不能替代安全巨段分步。

字体先评估相同实例的资源解析、outline 准备及上传是否重复。
仅当可见 IR 收口后 GPU／编码仍是主要瓶颈，才推进 LT-08 atlas 试验。
缓存键覆盖字体内容版本、变体、glyph、ppem、DPI、subpixel、AA 与 synthesis；
设备重置失效，任意变换和大字号有明确回退。
atlas 不改变布局 advance 或交互结果，不能假定 Lapce 的 Cosmic Text 路径
对 Vello 更快。

## 建议的评审与实施顺序

以下均为待评审工作包，只映射既有 LT 编号，不建立第二份执行队列：

| 顺序 | 工作包 | 对应切片 | 可评审结果 |
|---|---|---|---|
| 优先 | styled layout 分阶段计时、导出／复制归属及外部能力合同 | LT-00、LT-04 | 判断 shaping、换行和结果导出的真实占比 |
| 优先 | 原生覆盖证书与横向／纵向可见 IR | LT-03 | 有限输入 Full/Partial 对照及可见输出计数 |
| 随后 | 可选 shaping／换行分离，宽度变化复用 | LT-04 | 多宽度结果与完整布局等价，记录真实内嵌反馈 |
| 随后 | source delta、共享切片、安全局部 shaping 与换行检查点 | LT-04、LT-07 的来源部分 | 长段／长行局部编辑等价，最坏退化明确 |
| 按证据推进 | 持久高度／宽度摘要和局部位置发布 | LT-02、LT-07 | 后续位置复制减少，交互和墨迹一致 |
| 独立评审 | worker、渐进覆盖及 glyph atlas | LT-05、LT-06、LT-08 | 调度、预算、产品交互与设备生命周期 |

建议先把分阶段合同和原生可见输出做实，再扩大到安全巨段增量。
紧凑来源可先试验 delta／共享片段，完整海量文档 provider 不必提前进入首批。
引擎无法提供安全 shaping 证据时，仍可交付宽度变化复用和可见绘制，
巨段编辑的同步目标保留未达状态。

## 验证与成本门禁

正确性用同输入的完整计算作 oracle，比较文本来源、glyph/font/advance/offset、
行断点、视觉顺序、尺寸、inline placement、caret／selection 和实际像素。
除随机编辑外，明确覆盖跨节点连字、Arabic joining、方向控制、组合字符、
emoji ZWJ／regional indicator、CJK／Thai breaking、tabs、跨字体和宽度反馈。
失败、字体替换、来源删除、旧快照留存与不具备增量能力的外部引擎同样覆盖。
随机反例固化为可复现输入，不只比较截图。
delta 反例覆盖同位置插入顺序、检查点上的插入、删除覆盖端点、
多编辑合成、非法 UTF-8 端点、版本链断裂和 split／merge 来源归属。
inline 反例比较相同文字在不同位置插入盒、盒删除后文字重新相邻、
纯尺寸／baseline 改变及反馈改变结构的完整结果。
连字样本先确认测试字体与 features 的实际行为，不预设任意字体必然形成连字。

性能继续保留现有四个工厂、固定追加和完整独立会话分布。
增加段首／段中／段末替换、连续增长、分裂／合并段落、长行横向滚动、
多宽度和真实图文混排；逐次记录实际重算字节／cluster／行数、复制字节、
共享与留存分配、校验／发布、IR 与 GPU／present。
局部操作要报告扫描窗口与退化比例，不能只报告缓存命中或平均时间。
原 Large CPU 追加 p95 ≤ 16 ms、固定可见区查询及 IR p95 ≤ 4 ms 目标不变，
巨段目标按能力和输入另行冻结，不套用 Xi 的历史 40 µs。

### 完整编辑路径的成本账本

每个版本分别记录全段分析、段落物化、局部 shaping 和换行，
不能用局部探测窗口大小代替本次请求读取的全部内容：

| 阶段 | 工作量与时间 | 计数口径 |
|---|---|---|
| 源提交／变更规范化 | 接收、版本和范围校验、位置变换／合成 | mutation receipt、编辑数、旧新来源长度 |
| 文本物化 | 连续段落拼接、重新分配与复制 | 实际复制字节、次数；同版本命中与新版本物化分开 |
| 全段分析与字体选择 | bidi／script／边界及 fallback 输入 | 实际读取字节／code point、分析次数；不藏入局部 shaping |
| shaping 与右端探测 | 实际送入 shaper 的内容和输出 | 累计扫描字节／cluster、取证后缀、扩张次数及丢弃输出 |
| 换行／恢复 | 恢复验证、候选／emergency 断点扫描与新行 | 访问 cluster、生成行、段首前缀扫描和真实恢复分别记录 |
| 导出与位置组合 | glyph／source／inline／边框及位置投影 | 新增、复制、共享和留存数量／字节 |
| 校验与发布 | 局部证书、新组合快照及完整批次检查 | 依赖数、候选失败、安装时间及旧新 revision |
| IR／GPU／present | 可见查询、录制、提交与实际呈现 | 原生输出分母、覆盖退化、各阶段独立终点 |

每一类同时记录累计工作与去重输入规模：
同一字节被两次探测、重新分析或回退处理，累计计两次，
去重规模仅表示本次实际触及的不同输入，不抵扣预算或时间。
失败探测、额外右端 shaping、回退前的已完成工作和最终完整重算全部保留。
阶段墙钟使用嵌套的总耗时与自身耗时，避免重复归因；
请求总延迟直接测量，不能累加阶段 p95。

端到端从固定操作开始、经源提交，到同一目标源版本的完整稳定查询结束，
原 Large 按既有协议比较并保留独立源提交 receipt 尚待补齐的限制。
巨段连续编辑需另冻结操作起点、合并规则、目标版本及终点，
记录所有输入、成功、拒绝、取消和超时；不只统计局部任务成功的样本。
全段分析／物化的下限测出后，才按输入和引擎能力冻结巨段目标。
只有完整编辑路径与目标版本一致的结果可以验收 CPU 完成延迟。
worker 的 UI 可响应时间、局部 shaping 达标或随机等价通过均不能替代这一终点。
固定可见查询／IR 的 4 ms 验收还需固定 clip、宽度及输出分母，
不能用发生在 resize 之后的混合场景替代。

源 delta 与索引原则上可用现有依赖实现；分阶段适配增加资产和元数据，
Rope 增加路径副本，worker 可能复制字体上下文，atlas 增加纹理与上传。
依赖引入、Native release、Web Wasm／JS／字体及实际压缩传输、
首次加载和 worker 初始化需要同配置启用／禁用测量。
当前没有这些增量的产物或运行数据，体积收益和延迟收益均待采证。

涉及 `text.flow`、`text.interaction`、`graphics.context`、`paint.protocol`、
`damage.repaint` 和 `render.backend_session` 时，
按[API 语义账本](../../parity/draw2d/api-coverage.md)逐项核对。
新增分阶段、delta、检查点或发布合同须有最小 ADR 与外部消费者证明，
获批后才登记 [P2 backlog](../../roadmap/p2-delta-backlog.md) 的单一 Execute 切片。

## 审计响应与剩余证据

五条意见均采用。R01 的右端证据、R02 的接口边界由固定库源码支持；
R03 的确定映射、R04 的结构失效及 R05 的完整成本口径有助于消除实施歧义。
它们细化现有契约，不要求将未经证明的能力当作已实现。
下表各项状态统一为“已补齐设计响应，待复核”，意见关闭由后续复核判断。

| 意见 | 正文定位 | 处理方式 | 剩余验证项 |
