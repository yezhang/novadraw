# 《Novadraw 原理与图形应用开发》内容结构

## 全书主张

全书以“完成一个图形应用”为主线，用应用任务引出必须理解的引擎原理。

读者首先建立最短闭环：

```text
构造 Figure
-> 使用 FigureTreeBuilder 组装
-> 交给 Runtime
-> 分发输入与运行期更新
-> Host 驱动帧
-> Backend 呈现
```

需要模型驱动编辑时，再加入第二条闭环：

```text
业务模型
-> ModelAdapter
-> GraphicalViewer 投影
-> Tool -> Request -> EditPolicy -> Command
-> 修改模型
-> 刷新投影
```

引擎原理始终服务于这两条链：解释应用为什么应从某个入口调用，以及引擎如何保证
调用后的布局、坐标、输入、连接和像素结果一致。

## 读者完成标准

读完实践主线后，读者应能：

1. 选择 Core 或 Editor；
2. 用 `novadraw` facade 构造场景；
3. 区分 detached、build、attached、drive 四个生命周期阶段；
4. 通过 Runtime scoped mutable facade 修改已挂载图形；
5. 把平台输入和后端提交接到正确边界；
6. 构建滚动缩放画布、连接和模型驱动编辑；
7. 用契约测试和无窗口回放验证应用。

读完原理主线后，读者应能解释：

- 为什么树、边界矩形和父链变换是多条算法的共同事实；
- 为什么布局与绘制必须分阶段；
- 为什么输入回调不能直接重入修改图形树；
- 为什么连接、自由范围和编辑投影属于派生状态；
- 为什么稳定场景与后端提交完成是两个不同边界。

## 章节职责

### 导读：先选择开发路径

只解决三个问题：

- 本书适合谁；
- Core、Editor 和底层集成分别适合什么应用；
- 如何按任务选择章节，而不是线性读完所有内容。

### 快速开始：构建第一个图形应用

建立完整但最小的使用闭环：

- 运行仓库示例；
- 依赖 `novadraw` facade；
- 构造 FigureTree；
- 创建 Runtime；
- 使用 scoped mutable facade 更新；
- 接入输入和帧提交；
- 选择产品代码目录和后续阅读路径。

本章只使用应用开发者应依赖的公开入口。内部类型只作为链接，不进入示例主路径。

### 第 1 章：系统模型

解释应用调用如何进入一帧：

- 场景树需要维持哪些跨模块不变量；
- Runtime、Host、Backend 和 Editor 的边界；
- 四个生命周期阶段；
- 一次输入或模型变化如何形成稳定帧；
- 稳定发布、完成反馈和故障锁定。

### 第 2 章：几何与坐标

解决“为什么画的位置和点的位置必须一致”：

- 边界矩形、客户区、视觉边界和投影边界；
- 父内容域、节点本地域、子内容域和表面域；
- 视口与缩放如何进入同一变换父链；
- 应用如何查询变换，而不是复制坐标公式；
- 几何更新为何必须经过 Runtime。

### 第 3 章：图形树与绘制

解决“如何组织和呈现场景”：

- Figure、FigureNode 和 FigureTree 的职责；
- Builder 与 Runtime 的使用边界；
- 生命周期、叠放顺序和裁剪；
- NdCanvas、RenderSubmission 和后端；
- 自定义 Figure 的最小职责。

### 第 4 章：布局与更新

解决“图形如何得到尺寸，并在变化后形成正确新帧”：

- 如何选择内置布局器；
- 布局约束为何属于父子关系；
- 测量与排列的先后顺序；
- 运行期如何修改布局；
- 校验、重绘区域、命令录制和帧提交；
- 哪些内容只与 LayoutManager、Host 或 Backend 扩展者有关。

### 第 5 章：输入与交互

解决“平台事件如何变成稳定交互”：

- 平台适配器的最小职责；
- 命中顺序与坐标降域；
- 悬停、捕获、焦点和手势会话；
- Figure 原生交互与 Editor 工具仲裁；
- 退出、取消和销毁时的状态清理。

### 第 6 章：图层与视口

解决“如何构建大型、可滚动、可缩放画布”：

- 图层键与叠放顺序；
- 普通与自由范围图层；
- Viewport、RangeModel、ScalablePane 和 ZoomManager；
- Builder 阶段如何组装滚动缩放内容；
- Runtime 阶段如何滚动和缩放；
- 编辑手势中的边缘自动滚动。

### 第 7 章：连接与路由

解决“边如何跟随节点变化”：

- 何时使用 Core Connection，何时让 Editor 投影连接；
- 锚点、场景查询、路由器和连接图形的分工；
- 路由坐标域与依赖追踪；
- 分组路由的准备、校验和原子提交；
- 自环、折点和运行期失效。

### 第 8 章：编辑框架

解决“如何把业务模型变成可撤销编辑器”：

- `ModelId -> EditPartId -> FigureId` 三个身份域；
- ModelAdapter、EditPartFactory 和 GraphicalViewer；
- 选择、工具、请求、策略、命令和反馈；
- 创建、移动、连接、重连与折点；
- 应用实现 Editor 的推荐顺序。

### 第 9 章：扩展、验证与故障排查

把原理转成工程方法：

- 扩展 Figure、LayoutManager、Anchor、Router 和编辑行为；
- 单元、契约、无窗口和平台验证的分工；
- 按症状定位到模型、场景、坐标、派生状态或后端；
- faulted、retry、suspended 和 rejected 的处理差异；
- 发布一个图形应用前的检查清单。

### 附录

只承载查阅信息：

- 统一术语；
- `novadraw` facade 与领域模块地图；
- 内部 crate 和代码入口；
- 示例与验证入口。

附录不承担正文首次教学职责。

## 写作约束

每章优先采用以下顺序：

1. 本章解决的应用问题；
2. 读者需要记住的一条核心结论；
3. 最小概念模型；
4. 应用入口和短代码示例；
5. 必要的内部原理；
6. 常见错误与排查；
7. 下一步阅读与验证入口。

维护时遵循：

- 每个章节只保留一个主问题；
- 先给结论和使用方式，再展开内部协议；
- 公共 API 示例优先于内部结构摘录；
- 大段清单放入表格或附录，不打断因果链；
- 明确标记“应用开发者可跳过”的扩展协议；
- 不用 demo harness 代替正式公开 API；
- 正文只回答“引擎如何工作、如何使用、为何对用户必要、失败时如何处理”；
- 外部来源、功能对齐、方案选择过程、历史演进、路线图、审计状态和成书方法只用于
  作者后台核验，不进入正文、脚注或附录。
