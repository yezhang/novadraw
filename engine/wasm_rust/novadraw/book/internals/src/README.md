# 深入理解 Novadraw

本书从第一性原理解释一个二维图形编辑框架如何维持一致性、可扩展性和可恢复性。
它不以 API 查询或仓库贡献流程为主，而是回答：

1. 图形、布局、输入、连接和编辑为何必须共享同一份场景事实？
2. 一次状态变化如何沿固定因果链收敛为稳定帧？
3. 如何在不开放主流程控制权的前提下提供可组合扩展能力？

## 适合谁

- 希望系统理解图形框架核心机制的工程师；
- 需要设计 Figure、布局、事件、连接或编辑器架构的人；
- 在阅读源码前，希望先建立完整心智模型的 Novadraw 贡献者；
- 需要评估类似框架设计取舍的技术负责人。

如果目标是直接开发应用，请阅读

## 写作边界

本书强调长期稳定的概念：

- 权威状态、派生状态与临时状态；
- 身份、所有权与生命周期；
- 坐标、布局、绘制和命中的一致性；
- 固定执行管线与开放扩展点；
- 模型投影、编辑意图和撤销语义；
- 原子提交、故障隔离和确定性验证。

本书不承担：

- 罗列所有公开 API；
- 提供产品应用配方；
- 记录当前 roadmap 或审计状态；
- 指导读者修改具体文件；
- 复制 ADR、测试命令和仓库维护流程。

类型名可以用于精确表达概念，但章节不能依赖具体源码路径或行号才能成立。

## 阅读方式

前三章建立全局模型。第四至第九章解释图形核心，第十、十一章解释编辑框架，第十二章
讨论开放能力模型，第十三章把正确性、失败和演进原则统一起来。

章节按因果顺序展开：

```text
源状态
-> 结构与身份
-> 几何和布局
-> 派生状态收敛
-> 绘制与输入
-> 编辑意图
-> 原子提交
-> 可观察结果
```

## 完成标准

读完后，读者应能够：

- 从状态所有权解释一个图形框架，而不是从类名记忆结构；
- 推导绘制、命中、damage 和连接为何必须共享坐标事实；
- 解释布局收敛与帧提交为何是不同阶段；
- 解释模型、EditPart 和 Figure 三个身份域；
- 判断某项变化属于基础协议、横切能力、共享模型还是具体组件；
- 为新机制定义不变量、失败边界和可验证结果。
