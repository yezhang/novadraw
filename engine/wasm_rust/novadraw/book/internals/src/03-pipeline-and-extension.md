# 3. 固定管线与开放扩展

框架既要允许用户增加行为，又不能让任意扩展破坏布局、重绘、通知和提交顺序。

本章解释：

- 固定执行管线与可替换策略的区别；
- 为什么 Runtime 保留调度权；
- 扩展代码为何优先产生候选结果，而不是直接修改全局状态；
- prepare、validate、commit、publish 四个阶段；
- trait、descriptor、typed key 和 facade 的不同用途；
- 为什么开放扩展不等于开放主循环。

核心结论：

> 框架开放“做什么”的差异能力，同时固定“何时执行、如何提交”的一致性流程。

本章应使用“主流程骨架 + 插槽”的结构图，并比较三种失败设计：宽接口中的空方法、
中心枚举不断扩张，以及扩展直接持有 Runtime 可变引用。
