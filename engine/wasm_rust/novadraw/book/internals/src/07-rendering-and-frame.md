# 7. Damage、绘制与帧提交

正确绘制不仅要求生成新内容，还必须知道旧像素在哪里、哪些资源属于当前会话，以及
后端是否真正完成了提交。

本章解释：

- dirty region 与 surface damage 的区别；
- 为什么几何变化需要合并新旧视觉边界；
- 递归绘制、状态栈、裁剪和 Z-order；
- Graphics 与命令录制的职责；
- RenderSubmission 中的命令、资源、damage 和帧身份；
- 稳定场景、准备提交、后端结果和完成确认。

核心结论：

> 稳定场景只证明“可以生成这一帧”，后端完成反馈才证明“这一帧的提交生命周期结束”。

本章应以移动一个带边框节点为例，完整追踪旧区域擦除、新区域绘制、命令生成和完成
确认，并解释为什么后端不能反向修改场景状态。
