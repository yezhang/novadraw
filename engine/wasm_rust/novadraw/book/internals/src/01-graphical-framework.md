# 1. 图形编辑框架解决什么问题

图形编辑框架不是一组绘图函数。它必须让业务状态、场景结构、布局结果、输入目标、
连接路径和最终像素对同一次变化保持一致。

本章从以下问题建立全书模型：

- immediate mode 绘制为何不足以承担长期交互状态；
- retained scene 为什么需要稳定身份和树结构；
- 图形核心与模型驱动编辑器分别负责什么；
- 源状态、派生状态和临时反馈如何区分；
- 输入到模型、模型到像素的两条闭环如何连接。

核心结论：

> 图形编辑框架首先是一套一致性协议，其次才是绘制 API 和交互组件集合。

本章需要建立一张全局因果图，后续所有章节都应能定位到图中的明确阶段。读者完成本章
后，应能判断一个问题属于应用模型、场景运行时、编辑投影、平台宿主还是渲染后端。

本章不讨论具体 API，也不展开单个算法的实现。
