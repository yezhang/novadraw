# 11. Tool、Request、Policy 与 Command

编辑框架需要把连续输入解释成业务意图，同时保持取消、预览、执行和撤销之间的清晰
边界。

本章解释：

- Tool 为什么是带版本和目标锁定的手势状态机；
- Request 如何表达平台无关、模型无关的编辑意图；
- Policy 如何解释目标、生成反馈并贡献命令；
- Command 如何只修改模型并支持撤销重做；
- CompoundCommand 的执行顺序与失败补偿；
- Feedback 为什么不能提前写入模型。

核心结论：

> 输入不是命令，反馈不是模型，Figure 变化也不是业务提交；四者必须由明确协议连接。

本章应选取移动、创建连接和直接文本编辑三个案例，提炼共同编辑闭环，而不是分别罗列
每个工具的实现步骤。
