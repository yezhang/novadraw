# Novadraw 图形引擎核心原理（内容结构）

本书按因果链组织，而不是按 Rust 包（crate）或源码文件逐项罗列：

```text
输入/模型变化
-> 场景运行时事务
-> 图形树与通用节点状态
-> 布局和派生状态收敛
-> 计算重绘区域
-> 绘制命令录制
-> 渲染提交包
-> 渲染后端
```

编辑框架在图形核心之上形成第二条闭环：

```text
输入
-> 图形对象分发
-> 编辑工具
-> 类型明确的编辑请求
-> 编辑策略
-> 仅修改模型的命令
-> 命令历史栈
-> 模型变更通知
-> 查看器与编辑部件投影
-> 图形场景运行时
```

## 写作目标

- 从第一性原理解释引擎不变量及其设计动机；
- 同时描述概念关系、数据结构、算法时序、失败模式和验证；
- 用当前实现的代码锚点说明抽象如何落地；
- 区分外部参考事实、Novadraw 设计、当前实现与实施状态；
- 关键概念在每章首次出现时给出定义，正文优先使用准确、直白的中文；
- 为后续核心能力演化提供可维护的知识入口。

## 非目标

- 逐接口的用户手册；
- 复制 `doc/` 的规范全文或 roadmap 状态表；
- 逐文件源码注释；
- 以 `org.eclipse.zest` 定义需求或架构；
- 把归档的迭代渲染概念验证（POC）描述为当前主线；
- 把提案或未验收设计描述成已经实现。

## 章节结构

### 第 1 章：系统模型与设计公理

回答：

- Novadraw 真正维护哪些跨模块不变量？
- 图形行为、图形节点、图形树、场景运行时、平台宿主和渲染后端如何分工？
- 为什么使用代际 ID、单线程核心、效果队列和稳定版本？

### 第 2 章：几何、边界矩形与坐标协议

回答：

- 布局边界、本地边框盒、客户区、视觉边界和投影边界有何区别？
- 父内容域、节点本地域、子内容域、逻辑/物理表面域如何转换？
- 为什么视口与缩放必须进入统一的子内容变换父链？
- 边界变化如何原子地产生通知、失效与新旧重绘区域？

### 第 3 章：图形树、生命周期与绘制遍历

回答：

- 通用节点状态为何与具体图形行为分离？
- 树如何统一所有权、叠放顺序、绘制与命中？
- 图形自身、子节点和边框的递归绘制顺序是什么？
- 裁剪策略与自由范围溢出如何保持一致？
- 命令画布与渲染提交包如何隔离具体后端？

### 第 4 章：布局、校验收敛、重绘区域与帧提交

回答：

- 布局快照与布局输出为什么采用读写隔离？
- 为什么校验必须先于重绘区域计算？
- 派生状态工作列表如何收敛到稳定版本？
- 脏矩形如何沿父链转换为逻辑表面重绘区域？
- 渲染提交、资源全量快照/增量和后端会话如何组成可靠帧协议？

### 第 5 章：命中测试与输入状态机

回答：

- 为什么命中顺序必须与绘制顺序互为镜像？
- 悬停、指针捕获、焦点与手势目标如何保存？
- 图形回调为何只记录待执行效果？
- 分发结果如何实现图形控件与编辑工具的仲裁？

### 第 6 章：图层、视口、滚动与缩放

回答：

- 图层键与叠放顺序为什么分离？
- 普通图层与自由范围图层的裁剪语义有何不同？
- 编辑框架的标准根图层拓扑如何组织缩放域？
- RangeModel、Viewport、ScalablePane 分别拥有哪一份状态？
- 边缘自动滚动如何双轴推进并在同帧重投影反馈与操作手柄？

### 第 7 章：连接、锚点与路由器

回答：

- 连接路径、边界、本地点和运行时状态分别由谁拥有？
- 锚点如何通过可追踪场景查询读取几何与记录依赖？
- 路由器如何保持纯计算和类型安全约束？
- 扇出路由与正交路由为什么需要不同分组范围？
- 准备、校验和原子提交如何避免半条或半组路径？

### 第 8 章：编辑框架

回答：

- ModelId、EditPartId、FigureId 为什么必须分离？
- 查看器如何从稳定模型快照构造并刷新投影？
- 选择状态、编辑工具、请求、策略和命令分别负责什么？
- 连接编辑部件为什么不是包含关系子节点？
- 反馈、指针释放、命令历史栈和模型通知如何形成可撤销闭环？

### 第 9 章：验证、失败模型与扩展方法

回答：

- 如何把公理变成单元、契约、无窗口与平台验证？
- 哪些错误可拒绝、可重试，哪些必须进入故障锁定状态？
- 如何扩展图形对象、布局管理器、路由器、锚点与编辑行为？
- 如何更新书稿而不混淆设计、实现与路线图？

### 附录

- 术语表；

- 推荐检索与验证入口。

## 每章模板

新增章节或大幅重写时优先包含：

1. 问题与核心不变量；
2. 概念关系图或时序图；
3. 数据结构及所有权；
4. 算法步骤；
5. 实际接口摘录与代码锚点；
6. 与 Draw2D/GEF 的保留或 Rust 变体；
7. 失败模式；
8. 验证入口。

关键术语在每章首次出现时使用“中文名称（英文原名或代码名）”并给出一句话定义。
后文优先使用中文；代码标识符、命令和枚举值保持源码拼写。
