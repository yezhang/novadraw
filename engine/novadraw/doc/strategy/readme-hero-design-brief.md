# README 头图设计简报

类型：`product-strategy`

状态：`proposal`

更新日期：2026-10-28

## 1. 决策

Novadraw 的 README 应使用一张来自真实可运行样例的头图。头图负责让开发者快速判断：
Novadraw 可以支撑专业、可交互、可扩展的二维图形编辑器。

画面不能为了显得复杂而堆叠功能。复杂度必须形成可读的关系结构，并能从仓库中的固定
样例、数据和视口重现。若旗舰样例尚未达到这一标准，应先完善样例，再制作头图。

## 2. 传播目标

### 2.1 主要受众

- 正在评估 Rust 图形、Canvas、diagram 或 editor 框架的开发者；
- 需要布局、连接、输入、渲染和模型驱动编辑能力的工具开发者；
- 评估项目成熟度、工程质量和扩展边界的潜在贡献者。

### 2.2 希望产生的判断

读者看到头图后应能得到三个结论：

1. 这是图形与编辑框架，不是简单绘图库；
2. 它能处理具有层级、连接和编辑状态的真实场景；
3. 画面来自可以运行和验证的代码，不是概念稿。

头图的下一步动作是引导读者继续阅读 Quick Start、打开样例目录或运行旗舰样例。它不
承担解释完整架构和列举全部功能的任务。

## 3. 事实边界

- 只展示当前样例中真实实现的 Figure、布局、连接、文本、选择和编辑能力；
- 不补画尚未实现的 inspector、minimap、协作光标、AI 面板或发布功能；
- 不把 Studio 产品设计混入框架头图；
- 在图注或画面边缘使用 `Built with Novadraw`，明确这是框架构建的样例；
- 不使用第三方产品名称、商标、界面复刻或无法确认授权的素材。

## 4. 样例主题

首选主题是一个架构图或数据血缘关系编辑器。它能在同一场景中自然呈现 Figure 树、
分组、布局、连接路由、文本和编辑反馈，也符合开发者对专业图形框架的预期。

场景应包含：

- 具有明确层级的三个业务区域或子系统；
- 多种但一致的节点形态，用于区分输入、处理、存储和输出等角色；
- 可辨认的连接方向、折点和交叉规避；
- 容器、标题、端口、边标签及少量状态标记；
- 一个处于选择或编辑状态的对象，用真实反馈证明样例可以操作；
- 足够的空白，让读者能沿主要路径阅读，而不是看到一团密集连线。

节点文字应使用中性、可理解的示例数据。不要使用真实公司、客户、内部系统或带有业务
承诺的名称。

## 5. 画面结构

### 5.1 主体

关系画布占据主要面积。核心链路位于视觉中心，次要分支向两侧展开。节点、分组和连接
构成画面的主要信息，应用外壳只保留能证明编辑状态的必要控件。

头图应捕捉一个完整、稳定的编辑时刻，例如：

- 一个容器或节点被选中；
- 与其关联的连接保持高亮；
- 端口、选择框或折点反馈清楚可见；
- 其余内容保持正常状态，便于比较。

不要同时展示多个互斥工具状态，也不要用悬浮说明卡遮挡关系结构。

### 5.2 品牌层

- README 已有项目标题，图片内不再放置大号项目名或宣传口号；
- `Built with Novadraw` 作为小型签名，不与画布内容争夺注意力；
- 可使用 Novadraw 标志或字标，但必须保持足够留白；
- 不使用渐变横幅、装饰光斑、抽象背景或与样例无关的插画。

### 5.3 颜色与文字

- 以中性画布和清晰边界为基础，通过少量语义色区分节点角色和交互状态；
- 选择态只使用一种高对比强调色，避免多个元素同时争夺焦点；
- 连接线、端口和文字在缩小到 README 实际宽度后仍需可辨认；
- 字体优先使用项目可稳定加载的 Inter 与 Noto Sans SC；
- 不依靠颜色单独传达状态，重要差异同时使用形状、图标、线型或标签。

## 6. 输出规格

| 资产 | 建议规格 | 用途 |
|---|---|---|
| 静态头图 | `2400 × 1200`，2:1，2x 输出 | README 首屏主视觉 |
| README 展示尺寸 | 约 `1200 × 600` | 桌面端基准检查 |
| 窄屏检查 | 约 `720 × 360` | 小窗口与移动端可读性检查 |
| 文件格式 | 优先使用优化后的 PNG 或无损 WebP | 保持文字和细线清晰 |
| 文件位置 | `assets/readme/hero.*` | 稳定引用与版本管理 |
| 辅助演示 | 6 至 10 秒的短录屏，可选 | 展示拖拽、连线或撤销重做 |

头图应控制文件体积，不能明显拖慢 README 加载。最终格式由清晰度和压缩结果决定，不为
追求更小体积牺牲文字、连接和选择反馈的边缘质量。

README 必须为图片提供准确的英文替代文本，说明这是由 Novadraw 构建的关系编辑器样例，
并概括画面中的分组节点、连接和编辑状态。

## 7. 制作流程

1. 选定一个真实旗舰样例，固定场景数据、窗口尺寸、字体和初始视口；
2. 补齐影响画面可信度的布局、路由、文本和交互问题；
3. 为样例提供可重复的截图入口，避免每次手工拖到近似位置；
4. 在 Native 或 Web 的正式渲染路径中捕获无缩放原图；
5. 只进行裁切、压缩和品牌签名处理，不修改产品能力或伪造编辑状态；
6. 在 README 实际宽度、窄屏和浅深色 GitHub 页面中检查显示效果；
7. 记录生成命令、样例入口和对应提交，保证后续可以重制。

若 Native 与 Web 的最终画面存在可见差异，头图应选择当前交付状态更稳定的正式路径，
图注注明样例入口，不拼接两个无法直接比较的界面。

## 8. 验收标准

头图同时满足以下条件才可进入 README：

- 画面来源和当前仓库代码可以对应；
- 读者能先看到关系结构，再看到编辑状态和品牌签名；
- 主要节点、连接方向和选择反馈在 README 宽度下仍清楚；
- 没有展示未实现、不可运行或仅存在于 Studio 提案中的功能；
- 不会把 Novadraw 误解为图中那个终端编辑器产品；
- 图片在桌面和窄屏下不裁掉核心内容；
- 替代文本、文件路径和重制方法已经记录；
- `cargo xtask docs` 与 README 链接检查通过。

## 9. 明确不做

- 不制作只有 Logo、口号和渐变背景的宣传横幅；
- 不用节点数量和连线密度代替真实的信息结构；
- 不使用外部图库拼成无法运行的产品概念图；
- 不在头图中罗列功能、性能数字、兼容平台或路线图；
- 不在旗舰样例稳定前用后期设计掩盖布局和渲染问题。
