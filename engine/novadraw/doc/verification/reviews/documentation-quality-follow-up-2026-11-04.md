# 文档质量后续事项

类型：`architecture-review`

能力归属：文档治理；涉及 Core、Editor、backend 与 platform 的规范表达和证据导航。
本报告不裁定代码缺陷，不修改设计接受状态，也不建立新的生产执行队列。

日期：2026-11-04。基线：`09f49e47`，ADR 已收敛为 10 项。
分析实际目录为 `doc/`。本轮不扫描 Rust 实现，不重审第三方行为。

后续状态：用户已授权按本分析修订，DQ01–DQ08 的确定改动已完成，
结果和未解决的基线限制见[修订记录](documentation-quality-completion-2026-11-04.md)。
下文保留发现时的判断与扫描分母；修订后的正文从各专题当前入口读取。

下一步优先修复会让读者作出错误判断的规范条款和历史基线，再处理设计正文的
状态、重复内容与阅读路线。继续压缩目录数量的收益已低于这些工作。

## 范围与已有结果

排除 archive、冻结 evidence 和独立字体原始报告后，本轮扫描了 397 篇 Markdown。
其中 design 有 99 篇，verification/reviews 有 176 篇；后者包含独立历史记录，
不能计作 176 份现行规范。全域扫描用于发现候选，重点主题经过上下文核对，
没有逐篇完成所有技术契约的语义审计。

[前轮质量分析](documentation-content-quality-2026-11-03.md)中的 Q01–Q03 已有修正记录。
Q07 的 ADR 正文压缩已由
[归并记录](../../archive/adr-consolidation-2026-11-03.md)完成，design 内部的重复仍需处理。
Q04–Q06 和 Q08 在下面分别继续追踪，不把旧报告的全部发现重新计作新问题。

设计入口的可达性检查没有发现孤立 design 文件。现有
`cargo xtask docs` 通过 473 份 Markdown 与命令引用，说明基础导航可用；
本轮确认的问题主要发生在有效文件的正文或版本关系中。

| DQ02 | P1 | 历史评审的被审版本与链接目标不匹配 | 原评审对应准确的基线，修订稿有独立入口；无法取得的版本明确标记缺失 |

| DQ07 | P3 | 基础及跨层设计开头未明确能力归属 | 明确能力、状态 owner 和消费层；不把依赖层误写成能力归属 |
| DQ08 | P3 | 文档门禁不能发现本轮主要语义问题 | 对现行设计增加范围明确的元数据、替代关系、锚点和示例检查 |

### DQ01：把已接受的低 miter 修订同步回基础正文

归属：Core Graphics／backend 文档。承接旧 Q04、Q05。

[Graphics 扩展](../../design/rendering/p2-g01-graphics-extension.md#5-stroke-与包围盒)
第 125–126 行仍规定 miter limit 至少为 1；同一文件第 304 行的归并摘要却允许
有限非负低 miter 产生 Bevel。文件内部已经出现相反要求。

[AA 专题](../../design/rendering/shape-antialias-proposal.md#hairline-与低-miter-单独决策)
第 145、152 行也保留“至少为 1”和现有小于 1 错误继续有效的条款。
[低 miter 规范](../../design/rendering/low-miter-and-cocoa-sample-profile.md#低-miter-契约)
第 14–18 行已明确有限非负值、保留原参数以及小于 1 时的有效 join。
因此需要修正旧条款，不需要重新选择该行为。

AA 专题第 134–137 行还要求默认比较 Native／Wasm 及传输压缩体积。
这与 [项目规则](../../../CLAUDE.md#包体积与性能要求)中的按用户明确请求执行不一致。
性能、内存、上传和覆盖成本仍须保留，不能把取消自动体积比较扩大为取消性能验收。
Core 零宽不绘制、样例 Cocoa profile 的零宽映射与通用 hairline 也必须保持分离。

### DQ02：让历史评审链接到真正被审的版本

归属：verification／archive 的证据关系。

[FR-02 草案评审](adr-060-draft-review-2026-11-03.md#评审范围与依据)
第 15–21 行声明行号对应被审版本，ADR 链接却指向
[原编号 060 的修订 1 快照](../../archive/adr-consolidation-2026-11-03/original/doc/adr/adr-060-flow-assembly-reuse.md.txt)。
该快照第 8 行标记修订 1，第 34–37 行已经补齐共享文字内容选择；
草案评审第 63–66 行则指出 ADR 尚未纳入该选择并要求补充。
两个文本分别处于修订前后，不能将现有链接当作被审版本的准确定位。

草案评审对复用合同和验收矩阵的链接也指向可变的当前正文。
文件存在、原稿哈希正确，只能证明保存了这些字节，不能证明它们就是对应评审的基线。
上一轮按文件角色重定向链接，没有充分核对这层版本对应关系。

建议为历史评审记录被审文件集合、版本或提交，以及必要的哈希；
当前方案另设明确入口。先查找实际的评审前版本，无法取得时标明基线缺失，
保留原判断和可核对引文，不拼造旧稿，不让修订 1 代替旧版本。
先处理 FR-02，再按相同规则抽查其他逐轮复核记录。

### DQ03：清理设计正文里的旧 ADR 前置要求

归属：设计治理。不是清除所有历史编号。

[长文本总方案](../../design/architecture/long-text-performance-proposal.md)
第 22 行仍要求获批后“形成最小 ADR 增量”；
[GEF 示例接入方案](../../design/editor/gef-official-examples-parity-proposal.md)
第 168 行要求在接入 ADR 中固定释放职责。
这些句子把具体设计收敛与 ADR 创建直接绑定，容易重新产生普通方案占用决策编号的问题。

[DisplayList 候选](../../design/rendering/display-list-protocol.md#7-二进制格式要求)
第 145 行也以 ADR 接受作为二进制格式的前提。
该场景可能确实涉及长期兼容边界，应逐项判断；不能把它与普通宿主接入一并机械删除。

[知识维护](../../knowledge-maintenance.md#冲突与替代关系)第 28–29 行目前明确 ADR 的
替代效力和范围更窄的规范优先，但未同样明确独立接受的 design 如何替代旧 design。
建议补齐独立接受的范围、修订关系和依据记录，避免迁出 ADR 后出现效力解释空白。
历史身份可保留，当前条件应使用专题名和真实合同。

### DQ04：区分当前合同、示意 API 和实施记录

归属：Core Query／Flow／图布局，以及局部接受的性能方案。承接旧 Q06。

[查询规范](../../design/architecture/query-identity-and-failure.md)第 10 行声明已完成行为验收，
第 193–195 行仍用“不代表迁移已完成”和“建议返回值”介绍接口表。
需要说明哪些是现行规范签名、哪些只是协议角色示意，并给出准确调用入口。
这不等于必须通过改文档来迁就代码现状。

[结构化 Flow](../../design/architecture/structured-flow-layout.md)第 10 行声明已接受并实施，
第 43 行保留拟定骨架及名称可调整，后半篇又展开“已提供”“已增加”的实施叙述。
[有向图规范](../../design/architecture/directed-compound-graph-layout.md)第 10 行声明已实施，
第 59、111 行仍介绍拟定字段和协议。
[图投影准备的整理前快照](../evidence/document-quality-2026-11-04/graph-preparation-before.md.txt)
当时明确保留实施前基线，已经避免直接状态矛盾，但该基线和大量完成流水仍在日常规范路径中。
当前规范另见[图投影准备](../../design/architecture/graph-projection-preparation.md)。

建议规范只维护正常行为、失败、范围和必要成本，完整实施事实进入 verification。
说明性代码明示不能直接照抄，精确调用链接到公开 API；仍未冻结的接口角色保持候选。
局部接受的长文本方案按切片区分效力，不因标题带 proposal 就整体改成规范，
也不因前几片已接受就给后续候选授予效力。

### DQ05：将共用合同收敛到一处完整正文

归属：Core 扩展和公共 API 文档。承接旧 Q07 的 design 部分。

[Capability 模型](../../design/architecture/figure-capability-model.md#9-mutation-协议)
第 300–314 行维护完整提交骨架；
[组件更新](../../design/architecture/component-update.md#3-执行顺序)
第 48–73 行又维护同一顺序、NoChange、失败与 panic。
Capability 的身份、发现和 descriptor 差异需要独立保留，
通用提交规则可以直接引用组件更新的对应章节。

[公共 API](../../design/architecture/public-api-contract.md)第 195–205 行已解释 owned／scoped，
第 219–223 行的归并段落再次表达相同权限。
第 207–229 行还按四个原编号逐段维护选择依据，部分内容已在前文给出。
这些是上一轮归并留下的重复，宜将必要的新信息合入所属章节，
原批准关系集中链接到归并记录。

先为这组规则确定正文责任，再处理文字、图文、资源等其他候选。
保留领域特有的前提和失败，不以两段用词相似就删除其中一段。

### DQ06：让入口描述当前归并结果

归属：总入口、归档入口和评审导航。

[总入口](../../00-index.md)第 9–10 行仍把“本次拆分关系”链接到前次分类；
[归档入口](../../archive/00-index.md)最后一项也是 59 篇的前次分类，
没有列出随后 52 → 10 的归并。
前次分类是有效历史，当前读者应先看到最新决策入口和最新归并记录。

[评审入口](00-index.md#当前专题)仍将 Q04–Q08 整组标为待处理。
应明确 Q07 的 ADR 部分已完成，design 去重仍待做，同时承接本轮发现。
扫描发现 48 篇 design 正文仍含迁出编号，这只是定位候选；
原批准身份无需删除，当前 API、实施条件和算法要求应改用对应专题与章节。

完成时区分历史基线链接与现行规范链接，不为提高链接通过率把历史判断指向新正文。

### DQ07：补明确的能力归属和阅读前提

归属：基础设计及跨层专题。承接旧 Q08。

[静态结构](../../design/architecture/static-architecture.md)、
[文字布局](../../design/architecture/text-layout.md)、
[目录设计](../../design/architecture/directory-structure.md)和
[图文整合](../../design/rendering/text-graphics-integration.md)的开头仍未明确能力归属。
正文可以推断部分职责，但跨层读者需要自行判断哪些是 Core 规则、
哪些由 backend 或 platform 执行。

扫描得到 50 篇前 25 行没有“能力归属”字段的候选，需要逐篇核对，
其他写法可能已经表达归属。
优先补基础阅读入口与跨层设计，区分能力 owner、状态 owner、依赖和消费者。
对只表达内部所有权的结构图、无法独立编译的代码和仍待冻结的接口说明阅读前提。
不增加没有信息价值的模板字段。

### DQ08：补会发现真实误用的文档检查

归属：文档工具和维护流程；本轮仅提出建议。

现有门禁在 DQ01 的相反准入条件、DQ02 的错配版本和 DQ04 的混合状态仍存在时通过。
因此应明确门禁证明什么，并补相应检查，而非给全文增加形式检查数量。

建议先检查现行设计的能力归属、候选与接受范围、正文可达性和本地标题锚点。
迁出编号用于当前语义且没有专题链接时提示人工复核，历史编号和冻结证据豁免。
替代关系检查要发现已生效的新条款仍与旧条款并存，以及历史评审指向错误版本的候选。

API 示例分成可执行示例与协议示意；只对前者绑定已有编译入口，
不能宣称所有 rustdoc 之外的文本代码已经可运行。
这些工具改动需单列实现和适用范围，不在文档分析中顺带修改测试或冻结材料。

## 建议推进顺序

先处理 DQ01、DQ02，消除规范误用和证据错配。
接着按专题完成 DQ03、DQ04、DQ05：修订效力、当前行为与唯一正文一起检查，
避免又产生一轮互相引用的补丁。
DQ06、DQ07 随所属专题同步；DQ08 根据实际修正案例形成有限检查规则。

本清单是文档治理建议，没有改变 P2 的生产执行顺序，也没有重新要求创建 ADR。
历史 review 的原判断和证据字节保持，当前入口只表达最新承接状态。

## 交付检查与限制

本轮只新增报告并更新评审导航，没有修正源规范或修改 Rust。
文档类型、数字、状态与出处已按 technical-writing-clarity 核对，
中文再按 haohao-shuohua 回读；对历史缺失和候选统计保留限制。
尚未做独立读者复述、全量技术语义审计或实现行为验证。

加入本报告后，`cargo xtask docs` 通过 474 份 Markdown；`git diff --check` 通过。
本次新增报告和导航的本地路径及标题锚点检查未发现新问题。
中文机械扫描发现 1 处对比句式候选，已改为直接说明；半角标点、
机械编号标题、空泛元话语和破折号均为 0 命中。这些结果只覆盖文字及导航检查。
