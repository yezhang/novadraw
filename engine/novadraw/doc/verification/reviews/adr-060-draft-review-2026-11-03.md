## 候选版本变化必须明确影响本次结果

追踪 ID：FR02-DR01。优先级：P1，接受前优先处理。

位置：复用合同“冷路径、命中与发布”，第 143–149 行；
验收矩阵 FA-R17、FA-R19。

合同要求版本变化时“拒绝该候选”，随后又允许候选作为本次计算的私有输入。
这容易被理解为只禁止安装缓存，仍可返回由不同版本拼出的尺寸或准备结果。
合同也尚未清楚说明，扩展声明版本如何参与最终发布重验。

修订要求：

- 区分缓存安装资格与本次结果有效性。明确参与者或依赖版本前后不一致时，
  measure／prepare 是否失败、由谁检查、返回什么结构化错误及保留什么旧结果。
- 说明 contributor、handler、border 及外部输入域的声明版本，如何从首次捕获
  进入调用末次检查和最终 preparation／Runtime 发布重验；不能只写“保留重验”。
- 区分普通缓存输入不匹配、构建期间输入变化与发布前输入变化的处理。
  普通 miss 可以重建，不能因此将同次计算中的版本不一致降为普通 miss。
- 保留首次值，禁止以后读值覆盖首次值来证明一致；保留现有预算、错误及无界重试限制。

复核标准：FA-R17 分别观察“不安装过期资产”“不返回过期尺寸”
“不发布过期快照”。增加末次局部检查通过后、最终发布前外部版本再变的反例；
明确该用例的检测入口与结果。新增用例在实施前冻结，当前不得标为通过。

## 共享文字内容资产需要进入 ADR 决策范围

追踪 ID：FR02-DR02。优先级：P1，接口冻结前处理。

位置：ADR 第 19–20 行；复用合同“资产与所有权”，第 36–43 行；
验收矩阵 FA-R23。

ADR 只概括完整组装结果缓存，设计却还要求新增公开共享构造，并改变
`StyledTextRequest` 内容存储和计费方式。该增量涉及 Core 文字请求协议，
不能只作为 Flow cache 的实现细节带入。

修订要求：

- 在 ADR 中单列共享文字内容资产的架构选择，说明它为何是避免请求构造重新复制
  全文和 spans 的必要条件。具体类型与构造机制继续由设计维护。
- 明确能力、公开 API 与状态 owner，列出 owned／shared 构造、内容校验、
  clone 和留存计费的迁移范围及兼容性影响。
- 保持外部文字引擎读取同一公开请求，内置与外部构造走同一受检路径。
  不暴露 Parley 类型，不提供仅内置可用的可信构造入口。
- 同步 ADR、设计与矩阵的范围说明，避免把该迁移排除在实施验收之外。

复核标准：从 ADR 能看出本片包含文字请求资产增量及其理由；
FA-R23 和公开 API／消费者验证覆盖 owned 与 shared 构造、非法 span、
当前 boxes／constraints 校验和共享留存。具体签名仍需接口评审，不能按本记录
直接推断已接受。

## 明确命中省掉的工作与保留的扫描

追踪 ID：FR02-DR03。优先级：P2，性能口径冻结前处理。

位置：ADR 第 22–24 行；复用合同第 110–131、136–155 行；
验收矩阵 FA-P02–FA-P04。

ADR 写“省去整页贡献读取与组装”，设计仍要求完整成员、静态输入和动态版本检查。
命中路径可能继续遍历整树；该表述容易让读者将贡献执行与依赖扫描混为一谈。

修订要求：

- 明确命中省去 contributor／handler 执行及组装结果重建，保留必要的依赖扫描、
  声明读取、完整比较和观察回放。
- 区分组装遍历与命中验证遍历；不承诺首片消除全部 Figure 遍历。
- 性能验收同时比较被省掉的工作与新增检查、共享消费的成本，
  保留 cold、miss 和不合格页面的分母。
- 延续归因报告的限制：细阶段计时有扰动，其阶段耗时不能直接作为可回收收益；
  生产净收益需要重新冻结匹配基线。

复核标准：ADR 的收益描述与设计算法一致；FA-P02–FA-P04 能分别观察回调、
组装、成员扫描、声明读取和消费成本。不得以缓存命中率替代端到端收益。

## 旧 lease 存活时需要完整容量合同

追踪 ID：FR02-DR04。优先级：P1，容量接口冻结前处理。

位置：ADR 第 25 行；复用合同第 34、45–48、170–188 行；
验收矩阵 FA-R20、FA-R21、FA-P05。

ADR 要求旧 lease 受容量约束，矩阵又要求容量缩减或服务销毁后旧 lease 继续合法。
目前尚未明确已有 lease 超过新容量时的处理，也未明确服务销毁后谁持有留存账本。
最后 lease 释放后扣账的要求，仍不足以定义容量行为。

修订要求：

- 区分 cache 驻留上限、全部存活 backing 的留存计费及单次 preparation 预算。
  说明各自控制新增准入还是约束已有对象。
- 明确容量缩减时已有 lease 的合法性、超限状态与新增准入条件。
  不因缩容修改或强制释放仍被外部持有的合法不可变资产。
- 明确服务销毁后账本的 owner、共享 clone 的责任域，以及最后 lease 释放的扣账机制。
- 保留唯一 backing 计费与子范围钉住完整 backing 的规则；
  不将逻辑预算单位称为实测字节。

复核标准：FA-R21 增加容量缩减后旧 lease 超限、外部长期持有、
服务销毁后释放以及共享 clone 的用例；FA-P05 分开报告驻留、候选、
外部 lease 与真实分配。容量默认值及增长前 charges 在实施前冻结。

## 分开架构接受、实施完成和生产启用

追踪 ID：FR02-DR05。优先级：P2，接受流程明确前处理。

位置：ADR 第 43 行；复用合同第 190–196 行；
验收矩阵第 76–79、95–97 行。

ADR 将已实现外部消费者证据同时列为“接受与实施的退出条件”，而生产实现尚未
授权。这容易形成先实现才能接受、先接受才能实施的流程循环。

修订要求：

- 分别定义架构接受所需的接口和消费者可行性证据、实施完成所需的可执行行为验证，
  以及生产启用所需的净收益、容量和回退指标。
- 若接受前确实要求可编译消费者原型，明确原型的范围、依赖与授权边界；
  不把原型自动视为生产实施。
- 保留独立 crate、不改 Core、同注册入口与错误通道的要求。
  拟议 target 仍标为不存在，未执行用例不得写成已通过。
- 冷路径回退容限、容量默认值和启用条件需要评审冻结，
  不在本次交接中补造数值。

复核标准：接受条件无需循环依赖未经授权的生产实现；
每项证据归属唯一阶段，架构接受不等于实施完成或默认启用。

## 明确接受后对 ADR-051 的局部修订效力

追踪 ID：FR02-DR06。优先级：P2，接受文本形成前处理。

位置：ADR 第 7 行；现行精确布局设计第 30、39–40 行。

提议状态下“不覆盖 ADR-051”成立，但 ADR-051 的关联现行合同仍要求每次重读贡献。
ADR-060 接受后需要明确局部例外，避免两个有效合同同时给出不同要求。

修订要求：

- 保留当前提议状态；写清拟议的接受后效力，而非提前修改接受日期或批准状态。
- 明确完整声明与依赖检查通过的页面允许省略贡献执行，
  其余页面继续遵循 ADR-051。
- 保持完整布局、来源几何、真实 inline 测量与发布一致性要求；
  不借组装资产扩张为完整测量或整页快照复用。
- 接受时同步现行精确布局设计的贡献重读条款，并链接 ADR-060 的局部修订。
  ADR 保留选择与效力，完整机制仍归专题设计。

复核标准：能够明确回答声明齐全、任一参与者无声明及依赖不足的页面分别遵循
哪项合同；提议期间现行合同保持有效。
