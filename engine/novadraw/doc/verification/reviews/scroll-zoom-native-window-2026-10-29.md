## ScrollPane 的实际观察

两个 InternalFrame 初始完全重叠。拖动上层 `fixed 100x100` 标题后，
分别显示固定内容窗口与 `Flow layouts` 窗口。

| 操作 | 屏幕结果 |
|---|---|
| 标题拖动 | 上层内部窗口移动，原位置露出另一窗口 |
| 固定内容窗口右下角扩大／恢复 | 原先的纵向滚动条隐藏，恢复小尺寸后重新出现 |
| Flow 窗口右下角扩大 | Label 与图标按新宽度换行，显示更多内容 |
| 纵向 thumb 下拖／上拖，按下箭头 | 内容、thumb 位置改变；上拖后恢复靠顶部内容 |
| Flow 继续扩大再缩回 | 宽大区域中纵向条隐藏，缩回后出现；内容重新换行 |

正式 resize 操作先移动鼠标到边缘并留出状态更新时间，再发送按下与拖动。
最初按错误角坐标的尝试未计入通过范围。只验证右下角 resize，
没有重做八向 resize 或光标图像矩阵。
没有滚轮事件工具，本轮未执行滚轮输入，也未覆盖横向条。
ScrollPane 结果为可见行为检查，没有直接读取 Runtime bounds 或 RangeModel 数值，
不宣称完整恢复的整图像素一致。

## Zoom 的实际观察

从稳定初始画面开始，将 `< Zoom >` thumb 拖到左端、右端、再回左端；
文字、边框和 SVG 图标随缩放改变，超出区域按窗口裁剪。
随后按右箭头四次，画面恢复初始大小。
根据既有公式 `(value + 10) × 0.02` 和范围 `0..175`，
端点对应约 0.2／3.7，初值 40 对应约 1.0；计算保留上游 f32 舍入。
本轮通过屏幕行为确认端点变化，没有直接采集实际 scale 值。

拖拽从 bar 开始，经过 Canvas 并进入临时面板，再在面板内松开。
thumb 继续变化，证明已有捕获没有被面板中断；松开后再移动鼠标，
画面保持。最后将真实窗口从外框 1200×828 缩到 820×628，再恢复。

| 比较 | 像素框 | 结果 |
|---|---|---|
| 最小缩放与从最大缩回后的最小 | `(0,60,1200,1500)` | 0 差异 |
| 初始画面与四次箭头恢复 | 同上 | 0 差异 |
| 捕获松开后与再次移动鼠标 | 同上 | 0 差异 |
| resize 前后左侧无遮挡 Canvas | `(0,110,900,1500)` | 0 差异 |

resize 后临时 egui 面板向左上方收敛，原比较框受到面板遮挡，
产生 248,314 个差异像素。原始比较完整保留在收据中。
另取两幅都未被面板遮挡的左侧区域得到零差异，不将这一结果扩展到整窗。
Panel 的位置变化是现有浮动面板行为，本轮没有修改其布局。
