# 文字宽度复用可行性验证

类型：`verification-record`

日期：2026-11-02。能力归属：Core 默认文字引擎适配；
本轮没有修改 Editor、backend、platform 或 Core 生产协议。

结论：Parley 0.7.0 的不可变 shaping 模板克隆后重新断行值得优先接入验证。
三次独立顺序会话的长文总 P95 均下降约 88%～90%，
本轮完整导出字段与交互抽样比较全部一致。
这证明隔离候选的收益，没有证明 TextFlow resize 达到 16 ms，
也没有关闭分阶段 API 评审、原生绘制或整体 LT 验收。

## 实验回答什么问题

[增量排版提案](../../design/architecture/long-text-incremental-layout-proposal.md)
提出保留 shaping 模板，在宽度变化时复制到独占 Layout，再重新断行和导出。
关键问题是完整复制与输出会不会抵消省下的分析和 shaping。
本轮把这些阶段实际运行并分别计时，没有只测 `break_all_lines`。

Parley 源码事实：

- `Layout` 与私有 `LayoutData` 使用派生 Clone；模板复制不是零复制。
- `break_lines` 先 `unjustify`，`BreakLines::new` 清空旧行和 line item，
  从默认 breaker 状态重新断行，不是编辑检查点恢复。
- Core 当前 `ParleyTextInteraction` 直接接收 Layout 所有权；
  不必为了交互 provider 再克隆 Layout。Arc、来源 revision 计算和输出验证另有成本。

本轮先读当前默认适配及已安装 Parley 0.7.0 源码，再运行独立 Cargo package。
完整源码、锁文件、方法说明、原始观测和汇总见
[证据目录](../evidence/text-width-reuse-2026-11-02/README.md)。
构建使用 Apple M1 Pro、arm64、Rust 1.96.0、release 和 CommandLineTools clang。
系统其他负载未控制，未进行跨产品排名或 GPU／present 测量。

## 结果与范围

四组内容采用仓库内置 Inter、Noto Sans SC、Noto Sans Arabic、JetBrains Mono，
每组都有两个字号和 brush 范围。字体上下文在同进程内复用；
模板第一次生成单列，不计入热宽度切换。
每会话每负载每路径 8 次预热、96 次正式样本，两条路径交替运行。
三会话共 2304 个正式路径样本；各自的 P95 保留在原始汇总中。

下表是三个会话各自 P95 的中位数，不是合并样本的 P95。
总计时含模板复制或新鲜准备、断行、对齐、完整实验输出、
provider 所有权移动，以及阶段计时与 receipt 构造。

| 负载 | UTF-8 字节 | 新鲜完整路径 P95 | 克隆后断行 P95 |
|---|---:|---:|---:|
| 拉丁长文 | 54150 | 16.775 ms | 1.990 ms |
| CJK／阿拉伯文／拉丁混排 | 66000 | 17.588 ms | 1.892 ms |
| RTL／阿拉伯文／数字／拉丁 | 62250 | 22.596 ms | 2.373 ms |
| 小型复杂文字 | 71 | 0.036 ms | 0.004 ms |

长文三个会话的新鲜 P95 范围为 16.553～23.005 ms，
候选为 1.854～2.402 ms。小型负载第二会话为 0.053→0.015 ms，
相对下降低于其他会话；微秒量级结果不适合推导生产帧率。
首次模板生成仍需完整分析和 shaping，本轮没有消除首次工作。

正确性每会话包含 240 组比较：四负载、六次宽度请求、五种对齐、
两种模板来源。六次宽度包含 640→220→960→640 往返、极窄 1 和无上限；
640 重复请求也计入比较次数。对齐使用 Core 当前公开的
Start、Center、End、Left、Right。
模板来源分别为尚未断行的模板和已经居中对齐的旧布局。

完整比较所有导出的行范围与指标、positioned glyph 的 ID／位置／advance、
run 的来源范围、字体身份、字号、方向、brush、变量坐标，
以及 cluster 来源范围与 advance；旧布局末尾重新核对，保持不变。
caret、hit test、前后视觉移动及全文 selection 同样相等。
小型复杂文字遍历全部 code point 边界，大负载只抽样约 32 个边界，
不表示任意 Unicode 或所有 Core 交互动作已覆盖。

## 剩余成本

以下仍是三个会话阶段 P95 的中位数，不能相加得到总 P95。
候选的导出成本已高于模板复制，继续优化时应先核对 Core 实际输出分母。

| 负载 | 模板复制 | 重新断行 | 实验完整导出 | 复制阶段申请字节／次数 |
|---|---:|---:|---:|---:|
| 拉丁长文 | 0.147 ms | 0.568 ms | 1.463 ms | 1300096／5 |
| 混排 | 0.238 ms | 0.509 ms | 1.284 ms | 2185740／7 |
| RTL | 0.338 ms | 0.585 ms | 1.597 ms | 2922528／6 |

复制申请字节与次数为单会话样本中位数；模板没有行数据，申请量稳定。
计数包含 allocator 请求，realloc 记新的申请长度，
不等于逐字段复制字节、峰值存活内存或 RSS。
实验导出仍分别申请约 5.50／6.54／7.66 MB；
共享 glyph 与来源资产仍有价值，但不宜为追求零复制推迟首个可证明的宽度复用。

实验 provider 只接收所有权，没有构造 Core Arc、TextInteractionMap、
镜像变换、来源 revision 或完整输出验证。
实验也没有复刻 Core 的逐片来源映射、内嵌 baseline 修正和发布稳定化，
所以这里的“完整导出”只指上述实验字段，不能当作 Core adapter 端到端成本。
字体替换、source 编辑、真实 inline Figure 及多视图缓存淘汰均未进入测量。

## 接入条件

继续按[文本性能路线](../../design/architecture/text-performance-strategy.md)
推进宽度复用，把本轮证据补入既有分阶段提案。
先冻结统一可选能力的输入身份、结果、所有权和失败合同，
再接入默认引擎；未声明能力的外部引擎继续完整布局。
不按引擎具体类型或样例名称旁路当前 registry、request 校验和预算。

生产候选必须保留未断行的不可变模板，每次请求独占行结果。
内容、样式、方向、字体／fallback／revision 和 inline 结构发生变化时，
按声明重验模板；只改变宽度不自动免除其他依赖检查。
模板、候选和旧 lease 共存需受字节预算约束，不能只按条目数限制缓存。

下一次适配验证需包括当前 Core 全输出、来源映射、交互 revision、
正常及镜像方向、受约束 NoWrap、字体失效、外部完整回退、旧 lease、
真实 inline 尺寸和结构反馈，并重跑原 Large 的更新与 IR 分母。
本轮没有给这些尚未执行的验证填写通过状态。

文档交付前已按技术文档清晰度与好好说话做事实、逻辑和中文自审；
数值回查原始汇总，隔离实验与生产验收状态分别保留，没有独立评审。
