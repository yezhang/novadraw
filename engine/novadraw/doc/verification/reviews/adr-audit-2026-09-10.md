## 2. 主要发现

### F1 / P1 / 高置信度：通用组件写入口未闭合

原 ADR-003 要求 Runtime 为提交边界，ADR-006/009 只列内置 typed setter；
原 static-architecture 允许差异化 Figure，但没有自定义私有内容如何更新的统一契约。
若每个自定义 Figure 都要新增 Runtime 分支，无法满足通用框架目标；若借出裸可变
Figure，又绕过 revision、layout 和 damage。此处是契约缺口，不是断言代码一定缺 API。

修订：ADR-014 决策 1 定义 owned typed update、prepared value、校验与统一失效；
外部组件用例成为 D4.4 门禁。纯计算契约不等于 `&self` 的静态保证。

### F2 / P1 / 高置信度：Label 特例错误推广到约束布局

原 ADR-011 第 3 节和 derived-state-convergence 第 8 节规定 intrinsic 不依赖宽度，
presentation 不能 revalidate，又要求后续 TextFlow 复用。E4/E5 证明宽度变化可能改变
所需高度；将换行留到 paint-only presentation 会使 parent 布局无法得到正确尺寸。

修订：natural metrics、constrained measure、arrange/presentation 分开；只有单行
ellipsis/alignment 等纯表现变化不反馈 layout。保留 typed worklist 与非收敛门禁。

### F3 / P1 / 高置信度：detach 被误当作通用所有权迁移

原 ADR-013 第 2/3/5 节和生命周期规范要求移出 arena、换 ID、重写任意对象内部引用。
这不能仅靠节点 map 完成，尤其涉及共享布局/Anchor/组件状态。E1/E3 也不能证明
“为 undo 必须搬运活 Figure”。

修订：D4.3 先规范 reparent/dispose/contents 与 namespace；撤回 Core 通用活对象
迁移承诺。可选 unmount、owned extraction 和跨域重建分开设计，不提供假成功。

### F4 / P1 / 高置信度：生命周期与观察通知混层，原子性承诺过宽

原 ADR-013 要求提交不执行用户回调，却声称延续 Draw2D removeNotify 顺序；E2 中
该 hook 承担真实解绑。用户扩展和 Drop 又可能产生外部副作用或 panic。
事务 guard 恢复不等于用户对象恢复，更不等于可继续渲染。

修订：引擎提交、必要组件行为、稳定发布、外部观察分层；结构一致后再析构；
任意扩展 panic 默认 faulted，不承诺回滚外部副作用。

### F5 / P1 / 高置信度：Runtime listener scope 和历史事件语义不足

原 ADR-010 用 payload 过滤代替 scope，既不能表达随 Figure 销毁的订阅所有权，
也不能从 closure 推断清理关系。“全局唯一 ListenerId”还可能被解释为全局分配器。
原 ADR-002 的 flush owner 候选和“先不实现 listener”仍在现行正文中。
E6 与延迟 FIFO 的差异未明确：A -> B -> C 后回放 A -> B，当前查询实际是 C。

修订：Runtime/Figure owner scope、namespaced ID、事件 revision/sequence/old-new；
查询只读最新 stable scene，阶段事件只是记录。原 listener 自注销 FIFO 规则保留。

### F6 / P1 / 中高置信度：跨 Runtime session 接管缺少顺序前提

原 ADR-012 比较“更大/更小 session”，专题规范虽说明 generation 只在同域比较，
却未限定跨 Runtime 接管。A -> B -> 迟到 A 在“不同 namespace 替换 cache”规则下
可能重新接受 A。completion token 保护 CPU ack，不自动保护 backend 收到的旧提交。

修订：Core Host 必须串行 handoff 并停用旧生产者，首次接管必须 Snapshot；
并发 handoff 需独立 activation token，当前不声称支持。未进行代码复现。

### F7 / P2 / 高置信度：路由组失败的两个表述冲突

ADR-008 “任一失败整组不提交”与 ADR-005/011 “失败清除旧几何并 unresolved”
需要区分计算结果拒绝与错误状态提交。否则旧 route/reservation 可能在文档上被要求
同时保留和清除。专题规范已规定保留失败依赖，不能报告为缺失恢复调度。

修订：拒绝部分成功 batch；独立完整失败 batch 清空组表现及 reservation、保留依赖。
Manhattan/Fan scope 的差异已由 ADR-008 正确修订，同步回 ADR-005。

### F8 / P2 / 高置信度：现行材料存在失效事实和多重所有者

- ADR-001 仍选 cosmic-text，而 ADR-007 已选 Parley。
- ADR-007/text-layout 仍写 Runtime/FigureTree 双候选所有者，与 ADR-003 不一致。
- text-layout 声称同一 TextLayout 同时承担自然测量与约束截断，与双缓存不一致。
- design/00-index 把已接受 derived-state-convergence 放在非规范提案中。
- UpdateManager 与 Layer/Freeform 的“同 generation 一次重算”未区分输入修订与
  整个 source epoch；后置反馈改变输入后必须允许再计算。

修订：同步当前正文、入口与缓存/服务所有权。历史实现报告不重写成新验收结果。

### F9 / P2 / 高置信度：constraint 默认接受与强校验保证不一致

原 ADR-009 允许第三方 LayoutManager 不覆盖 validate_constraint 即默认接受，
同时对外承诺 constraint 类型错误在提交前暴露。对内置 manager 的保证不能自动推广
到任意扩展。修订为显式声明约束策略；宽松兼容是可见选择，不是框架已验证其语义。
该项是保证范围修正，不断言 Draw2D 本身提供了 Rust 式强类型预验证。

## 4. 设计到实现的剩余门禁

按顺序推进，不恢复被撤回的旧编码计划：

1. D4.3：namespace、scope/共享绑定所有权、生命周期/fault 边界与 dispose。
2. D4.4：外部 typed component update/私有派生快照，以及受校验 TextLayout 构造。
3. D4.4：约束测量验证、历史通知与 stable query、路由失败 batch、session handoff。
4. D4.5/D4.6：性能与完整自动/Native/Web 回归。M10.5 仍在 D4 后。

接口评审必须给出自定义组件实际用例和失败所有权证明；文档里的 prepared update
不是已存在的 Rust API。旧 D4.1/D4.2 的 complete 只表示旧批次完成，新增验收尚待执行。
