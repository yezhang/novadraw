## 后续实施门禁

受检投影在进入新实施范围前，按修订稿冻结公开查询、input reader、capability
关联与替换、错误 source、单查询／整帧预算及 API snapshot 迁移。
这一步落定接口细节，不应重新改变已复核的权限、首次值或失败边界；
若改变这些语义，应对实际变化另行复核。

外部消费者优先验证受检与实时混合路径、非交换变换、共享值的查询间／查询内变化、
后续回调冲突、嵌套输入与循环、忽略错误、reparent、退休、预算拒绝和恢复。
同时验证 source revision 不变的唤醒、旧像素擦除及必要通知。
编译与执行证据属于后续实现门禁，本次没有将测试计划写成已有验证结果。

局部 drawing 目前选择完整进入状态 proof，平移导致 transform 改变时可以 miss。
这保留现行状态读取语义，但尚未证明位置无关的录制资格或拖动时 paint 省略收益。
录制接入复核须明确实际可复用范围，验证不可变段在所有 backend 的消费或拒绝路径，
并分别测量 paint 调用和 command／glyph 深复制；不能据本轮通过宣称该目标已达成。

索引及资产留存的具体预算单位、配置和错误仍在接入前冻结。
索引不得改变外部搜索策略的必要调用行为；包含未知策略或无法证明的包络时，
按现行语义保守处理。backend 的编码成功不能代替最终呈现与 Runtime completion，
显示前缀仅按既有匹配确认推进。

## 总体完成状态

本次复核解决的是设计回应是否足以继续分步推进。
已有局部正确性、active 成本改善和混合平移测试继续保留其原证据范围；
整帧尾部、混合大树、局部录制与 backend／platform 尚未完成的门禁不因此关闭。
后续按唯一 [P2 backlog](../../roadmap/p2-delta-backlog.md)维护实施状态，
各切片通过所属验证后再判断 Core 或跨层总体完成。
