# Shapes Inspector 布局分析

类型：`reference-analysis`

日期：2026-10-29

## 用户反馈与分析范围

用户认为 Inspector 属性查看窗口不够精致，希望判断原因是否来自 key 文本标签
对齐或分割线。此前还要求布局适度紧凑，注意文本和空间对齐，避免松散。
本轮仅记录分析；用户明确由新 Agent 修改。

分析依据为当前布局代码及本会话已查看的原生窗口截图。截图中 key 标签左边缘
基本对齐，分割线未见明显错位。问题主要来自属性行列关系、标题层级和留白组合；
不能把它直接归结为标签垂直错位或横线位置错误。

## 属性标签与字段之间缺少稳定的视觉关系

`property_grid` 使用两个独立 Grid，分别呈现 X/Y 和 Width/Height，列间距为
12px、行间距为 6px。标签采用小字号、左对齐；数值框使用剩余宽度，行高为 26px。
未显式规定跨分组共享的标签列宽。

短标签与长标签末尾到输入框的距离不同，X/Y 行容易显得左右分离。截图未证明两个
Grid 的输入框左边缘已经错位，但独立计算列宽在文字或面板宽度变化时仍需检查。

建议统一标签列宽，标签右对齐，文字与字段垂直居中；两个分组的字段左边界共享
同一条线。列宽按最长标签、字号和可用面板宽度确定，不凭截图随意补坐标。

## 数值框过于像按钮

DragValue 铺满剩余宽度，默认外观为较大的灰色块，数值居中。短数值占用很宽的
字段，使整个属性区更像一排操作按钮，属性标签与值的关系反而变弱。

建议局部减弱字段底色，评估数值右对齐，统一单位位置和内边距。保留输入、拖动、
聚焦和禁用状态的可辨识度；修改前确认 egui 0.35 的公开 API 是否支持所需对齐，
避免仅覆盖文字绘制而破坏编辑行为。尽量在 Inspector 内设置样式，防止影响工具栏。

## 标题层级重复

Geometry 包含 Position 和 Size，但三个标题都调用 `section_title`，使用相同的
大写、小字号、颜色和左边界，父子层级在视觉上难以区分。

优先考虑去掉 Geometry，只保留 Position 和 Size；若保留 Geometry，则明确区分
父标题与子标题样式。此建议尚未实施，不是新的引擎契约。

## 分割线周围的间距加重松散感

对象摘要后显式添加 12px 空间、分割线和另一个 12px 空间，还会叠加默认控件间距。
随后 Geometry 下再加 6px，Position 下再加 4px。对象摘要到第一条属性之间有较多
过渡空间和标题，用户容易感到信息被拉开。

建议先收紧摘要到属性区的距离，再判断是否保留横线。横线维持轻量，只承担分组；
不以加粗或增加横线来补救层级问题。Position/Size 组间距离应大于组内行间距。

## 建议修改顺序与验收

先统一标签列和字段对齐，再调整数值框外观，随后简化标题并收紧横线周围空间。
对象摘要图标与两行文字的中心关系可一并复核，当前未将其认定为明确缺陷。

- 检查最窄、默认和较宽 Inspector 下的标签、输入框和按钮边界。
- 检查短值、负值、小数与较长数值，不应截断或遮挡单位。
- 检查无选择、单选、多选主节点和连接选择的显示。
- 检查输入焦点、字段拖动、错误提示、Reset/Apply 和画布锁定状态。
- 保持属性投影、几何校验、命令提交、撤销/重做和选择语义。
- 运行受影响样例的测试及 Clippy，复核真实窗口截图；仅布局调整不需重复全量
  workspace 测试，也不应编写只复述样式常量的测试。
