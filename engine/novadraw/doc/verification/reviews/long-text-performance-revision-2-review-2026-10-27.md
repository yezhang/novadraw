## 实施时继续遵守的边界

首批索引的安全性来自保守包络和证书，不来自逻辑行顺序。
重叠严重或范围未定时允许退化扫描，必须记录实际候选和 run 内检查成本，
不能因可见输出少就宣称查询成本低。

layout 复用不免除 ink/paint 更新。
实际 provider 的范围无法证明时，先准备必要轮廓或保守回退；
新包络、索引与 damage 一致发布，候选失败不留下部分安装。
外部 contributor、border、engine 和 outline provider 共用受检入口。

异步精确模式选择整体稳定，保留了既有 stable epoch 与通知 FIFO 的权威。
同一 Runtime 的无关区域也会等待，这是方案明确接受的产品限制。
同场景局部帧、局部通知或渐进覆盖属于独立增量，不能在首批优化中顺带引入。

硬预算能力必须覆盖实际分配；Core 内部账本不能证明整个进程内存有界。
外部引擎没有可执行的分配上限时，保持明确能力限制。
预算失败不回滚已提交源、不丢通知、不强制释放旧 lease；重试创建新请求代次。

LT-00 先建立可恢复基线和真实驱动，再评价性能目标。
既有三次测量只证明问题存在；采样不足、失败未处理或实际呈现证据缺失时，
不能用成功样本或 GPU 提交时间替代相应验收。
