## 实现与契约验证

TextLayout 的行与 glyph run 存储不可变共享，绘制分片引用 run 范围。
StyledTextLayout 共享 request、run、placement 与绘制布局数组。
外部 root 通过 `FigurePresentation::shared_data` 留存同一 FlowSnapshot。
来源 fragment 索引与来源范围索引随快照构建。

段落缓存使用实例身份、完整 request 和 engine revision。
`TextLayoutEngine::cache_identity` 是所有引擎共用的可选合同；
未声明时完整重算。OutlineTextEngine 只在内部引擎声明合同后启用，
其 provider 变化仍进入 revision。宽度、inline box 与 paint style 不从 key 删除。
贡献、边框度量和真实 Figure 测量继续读取当前场景；
整页缓存命中重验并保留依赖观察。

最终 `text.long-layout` suite 通过：外部布局契约 5 项、绘制契约 4 项、
索引单元测试 3 项、structured flow 22 项，以及 1 项 GPU 测试中的 18 组对照。
suite 还执行原 Large 的 release CPU smoke；完整分位数另由采样脚本计算。
覆盖局部追加后未变段落共享、位置更新、旧快照留存、外部引擎退化、
宽度变化、字体替换、bidi、内嵌 Figure、外部边框和失败时保留旧发布。

## 第三轮：稳定化分段测量与只读输入复用

RuntimeFrames 新增默认关闭的实例计时开关和读取后清空的阶段记录。
计时覆盖 checkpoint、布局、准备输入、签名、callback、候选校验和发布，
记录包含子阶段的总耗时与扣除子阶段后的自身耗时。
失败返回同样结束计时；关闭时不读取时钟或创建计时记录。
Flow 构建和投影作为嵌套阶段计入，避免重复归因。

30 次探索样本的追加平均约 19.79 ms，Flow 构建约 10.61 ms。
构建外主要开销包括布局自身 1.89 ms、Flow 签名 1.67 ms、
批量校验 1.64 ms、发布 1.18 ms 和投影 0.92 ms。
这些是确定下一步的探索数据，不作为完整分位数验收。

同一个 PreparationScene 内的树与 resolved style 由不可变借用保护，
本轮复用其中的签名基础计算和字体描述符解析。
源签名与含派生几何的签名分别留存；外部 provider revision 每次仍重读。
预算失败不能被缓存命中掩盖，缓存不跨越 scene 生命周期。
FlowContributionContext 的既有 text_style 入口使外部与内置贡献共用字体解析；
颜色、字体资源选择与文字引擎版本仍分别走当前场景和引擎合同。

定向测试覆盖嵌套计时的独占核算、失败退出、实例隔离、
provider revision 更新、预算耗尽和不同字体描述符的隔离。
探索样本的 Flow 签名平均约降到 0.63 ms；
整体时间仍有波动，完整匹配采样完成前不据此宣称整体提速。

本轮使用上轮冻结源码加相同计时构建两份独立源码，
比较确认只在 `assembly.rs`、`protocol.rs`、`snapshot.rs` 和 `scene.rs` 有优化差异。
两份驱动、字体、配置和 Cargo.lock 一致，完整源码归档包含该 lockfile。
