# FigureTree 内容、布局与投影分离总体评审

类型：`architecture-review`

能力归属：Core（`novadraw`）FigureTree／Runtime 的依赖、局部资产、坐标与
帧发布，以及 Core Graphics 的中立绘制表达。backend 的编码、设备资源与
可选栅格复用分别验收；platform 承担输入与呈现。Editor 是几何消费者，
本次不提出新增 Editor 能力。

日期：2026-11-06。

## 总体结论与效力

**建议保留总体方向，补齐全链路合同后复审；受检 child transform 候选尚不建议接受。**

方案已明确整个 FigureTree 的范围，并正确区分局部内容、布局、投影和输出成本。
内置与外部共用扩展模型、未知回调保守执行、真实依赖继续更新、不承诺恒定帧耗时，
这些边界应保留。主要缺口是各阶段如何取得复用资格、依赖如何持续维护、
局部资产如何组合，以及多个阶段如何共同形成一致的稳定帧。

总体方案已有实施授权，本报告不撤销已授权切片，不将已通过的局部验证改判为失败。
新增公开合同仍按方案中各自的待复核范围处理；已有布局合同的效力由其所属专题维护。
本报告记录两轮设计评审的合并意见，不定义运行时合同，不授权新的实施范围，
也不将设计建议记为已实现或验收完成。执行队列继续由
[P2 backlog](../../roadmap/p2-delta-backlog.md)维护。

P1 表示在接受相应新增合同前应补齐的正确性或公开行为缺口；
P2 表示需要明确处理或给出依据的成本、验收与文档建议。
各发现均为被评基线的待处理事项，不是本次复现的实现缺陷。

## FT01：各阶段须分别取得复用资格

严重级：`P1`。位置：“目标与现行依据”“分开的状态及依赖”，22–57 行；
“通用更新路径”，89–108 行。

方案要求合格子树“不重新测量、布局、准备或复制”，但这些操作具有不同的
有效性条件。外部布局可以与位置无关，其 paint 仍可能读取绘制状态或产生 effect。
输入 proof 相等只证明已登记输入有效，不能自动证明未知回调可以省略。

建议增加阶段复用合同表，分别写明 measurement、layout、preparation、projection、
drawing 和 backend 资产的准入条件、输入、依赖、检查点与失败行为。
区分内容资产生成和当前投影／设备条件检查；复用内容不等于省略全部 preparation
工作。资格按阶段及资产判断，不用一个子树布尔值赋予所有阶段缓存权。

复审条件：给出同一混合子树中“布局可复用、绘制仍实时执行”的消费者；
未知扩展的保守处理范围由实际依赖决定，不能无依据扩大到其他独立资产。
缺少完整声明的扩展继续走现行路径，不能按 Figure 类型推断资格。

## FT02：实际依赖需要完整生命周期与收敛路径

严重级：`P1`。位置：“分开的状态及依赖”，50–57 行；
“不同拖动的行为”，69–76 行；“通用更新路径”，80–97 行。

“实际依赖改变时更新”没有完整说明依赖如何登记、找回消费者、替换和退役。
只记录曾经返回的节点，会漏掉 children 增删、顺序变化、查询为空或条件分支切换
等影响输出的事实。旧依赖过早删除还可能使失败恢复后的资产失去失效来源。

建议定义读取登记、反向查找、成功替换及失败保留的行为，覆盖完整身份、
结构事实、样式继承、资源和私有输入；说明 reparent、退休与能力替换的清理规则。
已知依赖环继续提前拒绝，预算不能代替环检测。

流程图可保留为概览，但应说明其省略的收敛路径。投影或布局改变影响 Freeform
extent、RangeModel clamp、anchor、route 或 locator 时，按现行阶段与工作集处理；
不能把所有下游变化固定为只更新 world transform。

复审条件：补齐依赖生命周期及阶段关系，列入增删极值 child、空查询变为有结果、
条件依赖切换、失败后恢复与跨子树连接反例。

## FT03：受检投影必须保留两类坐标边和权威来源

严重级：`P1`。位置：“受检 child transform”，214–239、262–266 行。

“局部变换边组合当前 bounds origin、Core insets 和额外 child transform”
没有区分坐标域，也没有明确保留现行 `local_transform`。新旧 provider 同时存在时，
尚未规定额外变换是替代还是叠加，以及准入失败后的分派。

建议沿用坐标 SSOT 的列向量语义：

```text
node_local_to_parent_content(N)
    = Translate(N.bounds.origin) * N.local_transform

child_content_to_node_local(N)
    = Translate(N.insets.left, N.insets.top) * projection(N)
```

分别绑定两类边的依赖和版本，再定义 world 组合。明确 projection 与 container 的
准入关系；已准入 projection 替代旧额外 child transform，只有合法缺失才走
实时回调。读取错误、退休与预算失败应传播，不能静默降级。
能力新增、替换和移除后的来源切换也须定义。

复审条件：覆盖非对称 insets、rotation、非均匀 scale、child placement 的
非交换组合及能力切换。有限奇异仍为逆向 `Ok(None)`。
坐标入口现已返回 Result，本次应描述为新增 projection/input 错误原因和传播行为，
列明受影响入口及包装方式，而非笼统称为“增加失败结果”。
实时回调的必要调用顺序与 effect 语义不能被缓存悄悄改变。

## FT04：查询证明须进入一致性与发布边界

严重级：`P1`。位置：“受检 child transform”，241–260、268–281 行。

“同一查询建立首次值证明”尚未说明多个坐标消费者与整帧最终检查如何衔接。
如果每次查询独立捕获新的 first proof，命中、路由和录制可能分别成功，
却消费不同共享值。首末值比较也不能单独提供并发快照保证。

建议明确历史 proof 与当前输入不同是缓存 miss，可按本次首次值重算；
本次首次读取后再发生变化是输入冲突，拒绝候选。Runtime 各消费者所消费的
贡献证明进入对应帧的最终检查；新旧输出替换和 proof 退出遵守实际消费关系，
不能给旧结果换一份新 proof 来接受。

独立树查询在整次公开操作成功后安装缓存，任一祖先失败不留下部分新前缀。
继承现行输入协议的稳定读取前提：外部状态在最终检查到返回／发布期间不得并发
写入；最终检查后不再调用能改变这些输入的扩展。
异步外部写入的稳定快照保证不属于已实现的基础证明能力。

受限 `ProjectionScene` 还需给出允许查询表，明确自身、其他节点、parent、
children 顺序、bounds origin、尺寸与样式的读取范围及依赖。
input 嵌套读取须保留传递 proof、循环拒绝、预算及不可清除的失败状态。
受限 scene 只封住 Core 提供的入口，`&self` 仍可能持有共享状态；
纯计算和完整输入声明是扩展者的合同义务，不能宣称类型系统封住全部绕行读取。

复审条件：定义独立查询和 Runtime 帧的 session／提交流程；
验证查询内变化、消费者之间变化、后续回调冲突、忽略错误及失败后重试。

## FT05：共享投影变化须触发工作、damage 和通知

严重级：`P1`。位置：“通用更新路径”，89–108 行；
“受检 child transform”，209–212、275–281 行。

假设共享平移从 A 改为 B，而 Core source revision 不变：
实时输入检查可以让查询返回 B，但上一成功帧仍显示 A。
方案没有明确共享值变化如何请求新帧，及查询缓存如何与稳定画面协调。

建议说明外部模型通过哪个既有入口请求更新，无请求时只保证哪些查询行为；
检测贡献变化后如何形成投影变更事实，并更新真实依赖消费者。
damage 的旧侧来自上一成功发布的投影，不能用当前 reader 重算并覆盖。
独立 FigureTree 查询只维护查询缓存，不自行驱动 Runtime 工作与通知。

clip 资产复用可以后置；本片采用新变换来源后，既有 clip、命中、damage 和
必需通知仍须正确，不能作为后续优化才处理。

复审条件：覆盖 source revision 不变的共享平移、old/new 擦除、未知 overflow、
坐标通知、失败帧保留旧画面及修正后恢复。

## FT06：局部 drawing 须定义录制输入与组合方式

严重级：`P1`。位置：“通用更新路径”，99–103 行。

现行 `PaintContext` 允许读取绘制状态。局部 recording 是否依赖进入回调时的
transform、clip、opacity 等状态，不能只从内容字段未变推断。
保留局部 recording 后若在 submission 组装时仍深复制命令，也未达到复制成本目标。

建议定义资产坐标域、受控录制环境或完整进入状态 proof、资源闭包、状态栈边界，
以及 self／children／border 的组合顺序。明确 Runtime 如何把不可变局部资产
组成当前 submission，保留 Graphics 错误与出版检查。
不再次执行 paint 和不深复制命令分别验收，不为此恢复 DisplayList proposal。

复审条件：用外部 painter 验证进入状态依赖、资源替换、绘制失败和组合顺序；
说明哪些资产可复用、哪些检查仍执行，以及命令／glyph 复制和分配的测量方法。

## FT07：空间索引与资产缓存需要范围和留存合同

严重级：`P1`。位置：“通用更新路径”，94–108 行；
“实施拆分与验收”，323–325 行。

“移动整个索引域”尚未定义索引域边界和包络有效性。
layout bounds、视觉墨迹、命中候选与路由障碍具有不同含义，不能直接互换。
多个缓存新增后，引用既有事务合同仍不足以说明其具体安装和恢复位置。

建议分别定义索引坐标域、包络来源及依赖，覆盖 overflow、效果外扩、clip 改变、
极值删除、隐藏恢复和重新进入 viewport。索引只提供保守候选，最终绘制顺序与
搜索策略不变；未知包络使对应范围保守处理，无法隔离的跨节点效果再扩大范围。

逐资产列出内部消费、缓存安装、stable 晋升、失败恢复、资源退休和设备恢复规则，
避免新投影与旧包络、旧 drawing 与新资源分别通过局部检查后形成不一致帧。
预算覆盖依赖、索引、旧状态、候选和 in-flight 同时占用；
淘汰后重建保持正确，读取或准入错误不能作为普通 miss 吞掉。

复审条件：增加索引生命周期、资产发布及留存预算表；
验证局部与扩大回退、资源／session 切换、预算拒绝及失败后恢复。

## FT08：总体成本须覆盖全树构造和祖先重读

严重级：`P2`。位置：“成本目标”，120–123 行；
“受检 child transform”，268–293 行；“实施拆分”，298–319 行。

能力成员索引回答哪些节点拥有能力，不等于本次哪些状态受影响。
完整回滚、样式构造、input 重验和资产交接仍可能带入全树成本。
world 矩阵缓存命中也可能继续承担全部祖先输入重读。

建议列出各阶段全树工作的原因、必要范围与后续负责切片。
真实消费者、通知和未获资格扩展的检查单独计数，结构构造与复制单独测量；
不为追求局部成本无依据删掉现行回滚机制。
成本模型增加树深度、查询数、共享祖先和未知扩展比例。
父链、reader、proof 合并与留存预算既覆盖单查询，也覆盖整帧累计工作。

复审检查：给出固定可见规模的节点数及深度扩张场景；
若屏幕外节点包含真实通知或共享输入消费者，其必要工作应进入分母，
不能把这类增长与无关全树扫描混为一谈。

## FT09：验收须能分别裁决正确性、工作量和净成本

严重级：`P2`。位置：“实施拆分与验收”，317–334 行。

既有场景清单较完整，但尚未明确总体关闭条件及 Core／backend 的独立完成范围。
活动交接和输入构造改善不等于局部绘制、编码或端到端拖动已通过。

实施记录的完整成员修正总基线中，reuse DragMove 的 active P50
为 23.0156 → 19.0363 ms，下降 17.29%；同组 frame P99 上升 23.38%。
后续 default 复验的 Wheel active P50 下降 2.36%，frame P99 上升 14.39%。
两组配置和基线分别保留，不合并计算收益；本次仅引用已有结果，没有重新采样。
这些结果支持继续分别验收阶段改善和稳定整帧收益。

建议明确以下完成条件，具体延迟目标和可接受回退依据匹配基线裁决，不预设数字：

| 门禁 | 要证明什么 |
|---|---|
| 正确性 | 对确定输入场景，对照完整计算路径的像素、命中、坐标、route、damage 与通知；未知回调另核对必要调用和错误行为 |
| 工作量 | 未变局部资产不再生成、命令不深复制、无关节点不进入派生工作集；真实通知与私有输入检查保留分母 |
| 净成本 | 关闭 tracing，匹配 cold／warm／miss／淘汰场景，比较各阶段和端到端 P50／P95／P99，保留回退及归因限制 |
| 层级范围 | Core 分离、backend 编码复用、可选栅格复用分别关闭，不以 Core 完成宣称 GPU 或整体交互达标 |

复审检查：外部消费者同时覆盖合格与未知路径、嵌套 viewport、Freeform、
跨子树连接、resize／reparent、私有变化、退休、预算失败和设备恢复。
混合平移的两项已有定向测试继续作为局部证据，不能替代混合大树或 GPU 完成验收。
平台采证按既有 roadmap 后置，保留未完成状态，不改写为平台已通过。

## FT10：总体正文应保留当前合同与必要状态

严重级：`P2`。位置：“下一布局切片的具体边界”，141–201 行；
开头状态与“实施拆分与验收”。

总体正文同时包含目标、候选合同和多轮构造整改经过，读者需要自行辨认当前生效范围。
建议将历轮样式／成员构造与采样过程归入现有实施记录，正文保留当前合同、
适用限制和简短状态链接。维护原始证据及各轮不利结果，不重写历史 bytes。

复审检查：明确已授权切片、待复核公开候选与总体未验收范围；
保留既有锚点或更新引用。执行状态由唯一 backlog 维护，
review 保存被评基线与发现，不成为第二份运行时合同或执行队列。

## 建议的修订交付与复审范围

先补齐阶段资格与依赖生命周期，再冻结受检投影的坐标、读取、session 和发布合同。
局部 drawing、空间索引及 backend 接入分别形成可评审的具体合同；
沿既有单链顺序推进，不把所有后续实现集中到当前投影片。

后续修订至少提供四份内容：阶段复用合同表、依赖及阶段关系、
资产发布／留存预算表、分层完成条件。它们可直接进入现有总体方案，
独立协议再按知识归属链接，不要求新建 ADR。
