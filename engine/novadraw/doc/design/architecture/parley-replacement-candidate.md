# 直接编排底层文本库的技术候选

类型：`proposal`

日期：2026-11-02。能力归属：Core 文字排版层。字体查询、文本分析、shaping、
断行与布局结果由 Core 编排；backend 消费排版结果并绘制，Editor 消费文字几何。

当前决定：用户明确要求暂时保留 Parley，把直接依赖底层文本库的分析保存为未来
技术方案候选。本文仅记录替代路径与评估条件，尚未批准替换实施，
不改变 [可选阶段文字协议](staged-text-width-reuse.md) 的既有授权与契约。
执行队列仍由 [P2 backlog](../../roadmap/p2-delta-backlog.md)维护。

## 候选要解决的问题

技术上可以去掉 Parley，由 Novadraw 直接使用 Fontique、Swash、HarfRust 和
Skrifa。但这些库分别提供排版所需的部分能力，不会自动组成完整的富文本排版服务。
采用该路径后，Core 需要接手 Parley 当前承担的编排、算法和布局数据维护。

候选价值是更直接地控制分析资产、宽度相关行结果、增量重排、缓存预算和操作准入。
这些属于待验证的设计收益；目前没有替代实现或同场景性能对照，
不能据此认定去掉 Parley 会更快。

## Parley 当前承担什么

分析基线为项目使用的 Parley 0.7.0，来源与生产补丁见
[依赖说明](../../../dependencies/README.md)。以下描述基于该版本的
[公开 API 说明](../../../dependencies/parley-0.7.0/src/lib.rs)、
[shaping 编排](../../../dependencies/parley-0.7.0/src/shape/mod.rs)和
[布局数据处理](../../../dependencies/parley-0.7.0/src/layout/data.rs)。

Parley 接收文字、样式和布局约束，输出行、字形、位置及文字几何。
它支持样式区间和嵌套样式树，协调文本分析、字体选择、shaping、断行、
双向重排与对齐，也提供行内盒子和光标、选择、命中定位等编辑基础。
实际字形绘制由渲染器完成；Novadraw 的 Vello 后端承担该职责。

文字与样式不变时，同一 `Layout` 可以重复断行和对齐；文字或样式改变时，
该版本通常需要重新构建布局。这是宽度复用的基础，生产缓存的计费、
依赖失效和资产生命周期仍由 Novadraw 的接入合同约束。

## 直接依赖底层库后需要接手什么

以下版本为 Parley 0.7.0 的
[依赖声明](../../../dependencies/parley-0.7.0/Cargo.toml)，
最终解析版本由 Cargo.lock 决定。

| 库 | 声明版本 | 当前提供的能力 | Core 需要接手的编排 |
|---|---|---|---|
| Fontique | 0.7.0 | 字体数据库、匹配、回退候选与资源缓存 | 按字符簇选择字体，协调回退与 shaping |
| Swash | 0.2.6 | Unicode 属性、文字系统、字符簇及边界分析 | 文本分段、双向文字算法与布局协调 |
| HarfRust | 0.3.2 | 给定字体和文本片段的 shaping，处理字形替换与定位 | 按样式、字体、方向和文字系统划分片段，保留来源映射 |
| Skrifa | 0.37.0 | 字体解析、指标与轮廓等能力；Parley 在布局中读取字体指标 | 汇总行高、基线和布局尺寸 |

Parley 0.7.0 的 shaping 由 HarfRust 承担，Swash 主要用于文本分析。
Parley 自身实现双向文字处理与断行等上层机制；
HarfRust 输出字形及位移，不负责整段富文本的换行与布局。

其余直接生产依赖包括 `hashbrown`、`linebender_resource_handle`，
以及可选的 `accesskit`、`core_maths`。Vello 和 WGPU 不属于 Parley 的
直接生产依赖；`peniko`、`tiny-skia` 等属于开发依赖。
未来候选应按实际职责重新确定依赖，不能把当前清单直接视为完整替代方案。

按 Novadraw 当前的富文本、多语言、图文混排与交互需求，替代范围至少包括：

- 样式解析，以及按字体、方向和文字系统进行文本分段。
- 字符簇安全的字体回退与 shaping 编排，保留字符、字形和来源之间的映射。
- 宽度相关断行、双向重排、对齐、行高、基线及 inline 布局。
- 光标、选择、命中定位所需的几何与逻辑位置关系。
- 分析资产、行结果、缓存和候选发布的生命周期、预算及失败处理。

简单固定字体的单行文字可以采用更小的编排范围，但该受限场景不能证明上述
完整替代成立。替代候选保持 Core 现有公开契约，第三方类型边界与统一扩展模型
仍按项目规则执行。

## 性能取舍与重新评估条件

去掉 Parley 不会自动消除 Fontique 字体查询、HarfRust 冷构造或 shaping 的成本。
直接编排可能减少中间复制、改善缓存粒度，并提供更明确的预算拒绝位置，
但也会增加算法维护、语义回归和依赖升级成本。
现有 [分析准入提案](text-analysis-admission-proposal.md)负责下层成本缺口，
本文不将这些缺口改判为必须替换 Parley 的证据。

当前继续保留 Parley，按既有合同推进宽度复用和成本控制。
未来若测量表明 Parley 的数据结构或执行接口持续限制目标性能、
精确增量或预算契约，再启动独立 Core 架构评审。评审前应补齐：

- 具体限制及反例，说明现有接入或维护补丁为何不足以解决问题。
- 替代层的最小范围、状态所有权、失败与恢复行为，以及外部消费者证据。
- 与 Parley 在相同文本、字体、宽度和功能下的语义及成本对照。
- 迁移、回退和长期维护方案，明确底层库升级后的复核责任。

对照需覆盖 CJK、RTL、混合字体、连字与组合字符、真实 inline Figure、
字体变化、极窄宽度和连续 resize。分别验证断行、来源映射、光标与选择几何，
并测量冷／热布局、尾延迟、峰值内存、分配、复制和缓存淘汰成本。
产物体积分析只在用户明确要求时执行。

上述证据完成并获得重大架构变更批准后，才实施替换。
当前候选不进入实施队列，不预占新 ADR 身份。
相关性能目标与技术组合继续由
[文本性能路线](text-performance-strategy.md)负责。
