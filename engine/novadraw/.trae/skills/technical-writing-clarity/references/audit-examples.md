# 审计案例与回归检查

按含义学习改法，不照抄右侧句式。以下案例取自项目文档表达审查；改写仅示范编辑动作，不覆盖原设计。原文可能继续修订，定位时结合章节与引文。

## 补足中文动作

原文：

> 其他 payload 保存“非文本 payload”的结构化分类与调用位置，不 Debug 任意 Any，不调用用户格式化器。

问题：保存对象与执行主体混淆；类型名被直接当成动词。

改写：

> 对其他 payload，只保存“非文本 payload”的结构化分类及调用位置。不对任意 `Any` 值执行 `Debug` 格式化，也不调用用户提供的格式化器。

检查：保留 payload 分类、位置和两项禁止行为，没有增加恢复或诊断承诺。

## 把拒绝条件写成条件

原文：

> 派生溢出、不可逆或无路径拒绝整个依赖该映射的候选。

问题：把失败条件写成“拒绝”的主语，修饰关系不顺。

改写：

> 坐标映射发生派生溢出、不可逆或没有转换路径时，拒绝依赖该映射的候选。

检查：只修复句法，不能顺带把三种情况合并成同一个错误类别或扩大拒绝范围。

## 把已有分支条件放回流程

原文：

> release 校验版本；需要时重算前述阶段，再清理反馈、构造一次 Command 和提交。

已有上下文：版本变化时丢弃旧结果并重算；反馈清理失败阻止提交。

改写：

> 释放指针后，先校验 SnapResolution 所依赖的版本。版本变化时，丢弃旧结果并重新计算。结果通过检查后，先清理反馈；清理成功后，再构造并提交一次 Command。清理失败时停止提交，并报告错误。

检查：分支来自已有上下文；单次 Command 与清理先于提交的顺序保持。材料没有说明的其他重算条件仍需补证，不能自行定义。

## 将复核论证从表格展开

原单元格：

> layout/ink/paint 分层并各带证书；轮廓、描边、DPI/覆盖变化进入正确失效范围；包络、索引和 old/new damage 同次安装；旧区域使用旧投影；未知轮廓先准备或不剪枝，不用默认轮廓预裁剪

问题：数据分层、失效传播、发布、旧区域处理和保守回退混在一格；“正确范围”没有解释。

改法：表内保留问题编号、状态和正文定位；表后逐项解释修订如何回应原问题。可先展开为：

> 修订将 layout、ink 和 paint 分层，并分别绑定证书；相关变化进入各自的失效范围。新包络、索引及 old/new damage 同次安装，旧区域仍使用旧投影。轮廓范围未知时，先准备轮廓或保留绘制，不使用默认轮廓预裁剪。

检查：这段只是结构改写。还须引用对应契约，解释范围为何足够；保留设计通过与后续实现验证的区别。不能仅换成段落就宣称论证完整。

## 前情不足时先记录缺口

原文：

> 已有提前退休反馈的清理拒绝不能替代真实 Core revision 耗尽。公开 API 没有安全的耗尽注入方式，继续保留两种 Tool 的端到端缺口。

问题：“提前退休反馈”及“两种 Tool”依赖未展开的前情，替代失败的理由不充分。

处理：查明已有测试的触发条件、revision 耗尽的不同条件、两种 Tool 名称及验收项。没有材料时不重写机制，可以明确已有结论：

> 现有清理拒绝测试尚未覆盖真实 Core revision 耗尽，该验收项继续保持未完成。

检查：其余原文事实仍需保留或在待补信息中明确列出。不能把“没有安全注入方式”改成“无法测试”，不能把未完成改成不需要验收。

## 保留清楚的反例

原文：

> 例如选择目标 B 中的节点 b，以及容器 A 中的节点 a，再一起拖入 B：b 需要重排或约束修改；a 需要 A 的移出和 B 的移入。按“每个原父都须允许移出”处理，会错误地要求 B 允许 b 移出。

这段可以保留。它交代操作情境、分别说明对象行为，再说明错误统一处理的后果。不要为了缩短文字改成“混合父批次须按关系分类”，把支持结论的反例删掉。

## 合理的形式应保留

以下句子是说明性例子，不是项目现状：

> 配置错误返回领域拒绝；服务已 faulted 时返回 fault，不能用“未变化”表示故障。

对比承担结果分类，不能只因有否定句就删。

> 先校验版本，再清理反馈，最后提交 Command。

编号或列表可以帮助表达顺序，不能按格式判为多余。若说明失败分支，应另补对应条件。

> 本轮通过设计复核，尚未验证实际性能。

第二分句限定证据效力，不能当成重复的免责声明删掉。

## 使用时的回归检查

创建或调整本技能时，用这些案例检查规则是否会诱导误改；它们是人工检查场景，不代表自动化测试已执行：

| 输入情形 | 预期处理 | 不应出现 |
|---|---|---|
| 条件被写成主语 | 补条件标记，保留错误分类 | 自动统一不同错误 |
| “需要时”有充分上下文 | 将已有条件写回对应步骤 | 增加新条件或调整先后 |
| 表格承载多层推理 | 摘要留表内，论证在正文 | 丢失依据或只改排版 |
| 项目符号未定义 | 查定义并链接；缺材料则指出 | 猜测 P、identity 或 owner |
| 原文含清楚的具体反例 | 保留支撑结论的信息 | 为简洁删除整个反例 |
| 有必要的对比、编号或限制 | 按功能保留 | 按命中次数删改 |
| 历史计划与当前状态混杂 | 标明时间和效力，引用状态入口 | 改写冻结历史结论 |
| 用户仅要求审查 | 给发现与建议 | 自动重写源文档 |
| 用户要求轻改 | 改允许的措辞，结构问题列建议 | 擅自重排章节 |
| 扫描器执行失败 | 明确报工具错误 | 输出干净或可读性通过 |

可移植到其他项目时替换案例出处；保留编辑动作与保真条件，不将 Novadraw 的业务规则推广成通用技术事实。
